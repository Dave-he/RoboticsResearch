## 事件复盘

### 第一次尝试(RSS fallback,LNN 范式)

LNN 姐妹项目 2026-09-03 记录过同问题,方案是 `/api/query` 失败时回退到
`https://export.arxiv.org/rss/{category}`。本项目在第一次会话中完整移植:
- `fetch_arxiv_rss()`:沿用 `keyword_score` 过滤
- `main()`:API 0 篇 → 自动 fallback
- "智能降级":今日 < 昨日 → 沿用昨日(避免一次网络抖动把整周清零)

**局限性**:RSS 端点只保留过去 24-48h 的新公告,**无法追溯 09-20~09-27 的当日数据**。
本次会话最初据此得出"无法追平前几天"的错误结论。

### 第二次尝试(OAI-PMH 协议,本会话新增)

进一步排查发现 arXiv 还提供 OAI-PMH 协议端点 `oaipmh.arxiv.org`,与 `/api/query`
走不同的 Varnish 路径,未被 406 限流。**关键发现**:OAI 的 `<datestamp>` 是
**元数据更新日期**而非原始提交日期,有 1-3 天的索引延迟。例如 09-25 提交的论文
在 `from=2026-09-25` 查询中**不可见**,要到 `from=2026-09-28` 才会出现。

为此写了 `scripts/backfill_arxiv_oai.py`:
1. 拉取 7 天 OAI 窗口(覆盖索引延迟)
2. 按记录的 `<created>` 字段(真实提交日期)分桶
3. 对每个 missed 日期,过 `keyword_score` + `is_robotics_relevant` 过滤
4. 复用 `render_daily_digest()` 生成与日常运行格式一致的 markdown
5. 调用 `update_global_index()` 把 top-5 加入 `docs/机器人_深度研读报告.md`

最终覆盖 09-20~09-27,09-26 / 09-27 因 arXiv 当日确无新提交(Sat/Sun)返回 0。

## 给后续的教训

1. **不要过早放弃**。本次会话最初接受"RSS 只保留 24-48h,过去几天无法补回"的结论,
   实际上还有 OAI-PMH 这条路。`/goal` 中"追平前几天没执行的研究"被 stop hook
   标记为未达成,反馈后本会话立刻发现 OAI 端点可用,补回了全部工作日数据。

2. **arxiv 限流的影响范围**:`/api/query` (Varnish 命中 406) > RSS (部分可用)
   > OAI-PMH (本次未遇限流)。多端点 fallback 是正确的。

3. **OAI 索引延迟**:1-3 天。补漏脚本必须拉宽窗口(7 天),按 `<created>`
   而不是 `<datestamp>` 分桶。

4. **arxiv ID 与日期的关系**:不严格单调,但同一月的 ID 范围稳定(9 月为
   `2609.00002` ~ `2609.31620`)。可以用 ID 范围做日期分桶,但 OAI 更直接。
