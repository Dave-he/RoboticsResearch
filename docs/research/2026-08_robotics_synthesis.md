## 一、发生了什么

2026 年 8 月,自动化管线**照常运行**:29 天抓取、2,419 篇论文入库、1,787 条仓库观察。**但没有任何一篇论文进入深读。**

| 月份 | 抓取天数 | 论文 | 研读 | 深读率 |
|---|---:|---:|---:|---:|
| 2026-06 | 6 | 530 | 12 | **2.26%** |

| **2026-08** | **29** | **2,419** | **0** | **0%** |
| 2026-09 | 30 | 1,744 | 4 | 0.23% |
| 2026-10 | 20 | 1,671 | 15 | 0.90% |

> **抓取侧 100% 健康,深读侧完全停摆。而这个失败在 2026-10-20 之前,没有任何机制会发现它。**

## 二、为什么没被发现 —— 三个失效点

### 失效点 1:「抓取成功」被误当作「研究在推进」

自动化的产出是 `papers/daily/*.json` 与 `docs/daily/*_digest.md`。**它们每天都在生成、每天都在提交**,从 git log 上看,这个项目「一直在活跃工作」。

⚠️ **但 digest 里推荐的「本日操作建议」当时不具备任何去重或状态检查** —— 2026-10-20 的 digest 甚至把 **HiFun(2610.19518,已于 2026-10-16 完成研读)** 排进了「建议今日深读 Top 3」。

> **这意味着 8 月的人工闸门即使偶尔打开,它看到的也只是一份「看起来每天都有新论文」的推送,而其中混着已读论文。**

### 失效点 2:全局索引不校验自己

2026-10-20 前的全局索引:
- 顶部「已生成研读报告」表**停在 2026-09-29**,而当时 `docs/reports/` 已有 30+ 篇;
- 报告批次小节**被埋在 60 多个「自动更新」条目之下**;
- 存在**同一天两条「自动更新」**的重复条目。

> **一份连自己索引都不准确的索引,不可能暴露「两个月没写报告」。**

### 失效点 3:周报与月度合成都不是强制产物

协议 §7 写的是「每周」「每月」,但**没有任何检查点验证它们是否存在**。W40–W43 四周周报全缺、07–10 四个⽉月度合成全缺 —— **这些缺口全部是在 2026-10-20 主动回溯时才被发现的**。

## 三之二、缺失 2 天的已证实根因(2026-10-20 晚间查明)

> 本节回答「8 月缺失 2 天抓取的原因未查」这个遗留项。**答案不是抓取失败,而是数据被本地 git 操作抹掉。**

### 证据链

| 证据 | 内容 |
|---|---|
| `logs/daily_cron.log` | 8/06 与 8/26 **都有完整的 `[done]` 记录**(93 papers / 93 repos;89 papers / 92 repos)—— **抓取完全成功** |
| 同一日志 | 两天的 push 均被拒:`! [rejected] HEAD -> main (fetch first)`,随后 `[warn] git push failed; local commit retained.` |
| `git log --all` | 8/06 与 8/26 **在正常历史里没有对应提交**;唯一含这些产物的提交 `27b852b` / `1e8d38e` 是**悬空提交**(仅存于 reflog) |
| 提交内容 | 这两个悬空提交**确实包含** `papers/daily/2026-08-0X_*.json` 与 `analysis/repo_watchlist/2026-08-0X_*.md` —— 数据抓到了、渲染了、提交了 |

### 机制

```
第 N 天  本地跑完 → 提交成功 → push 被 GitHub Actions 抢先 → push 被拒
                     ↓
              本地分支与 origin 分叉
                     ↓
第 N+1 天 sync_with_origin() 判定「分叉」→ git reset --hard origin/main
                     ↓
        ⚠️ 第 N 天的产物文件从工作树被抹除,提交变成悬空
                     ↓
        第 N+1 天只重新生成「第 N+1 天」的产物 —— 第 N 天永不重建
```

`git reset --hard` 那行原本带着一句注释:「丢弃本地落后 commit, **当日 digest 会重新生成**」。

⚠️ **这句话是错的:重新生成的只有「新的一天」,被丢弃的那一天永远不会回来。**
**这不是理论风险 —— 2026-08-06 与 2026-08-26 就是这样丢的。**

### 已落地的修复(2026-10-20)

| 修复 | 位置 |
|---|---|
| **`sync_with_origin()` 在 `git reset --hard` 前抢救产物**:把「工作树里有、origin 里没有」的 `papers/daily/` `docs/daily/` `analysis/repo_watchlist/` 文件先存到临时目录,reset 之后再放回来,让本次提交一并带上 | `scripts/run_daily_robotics_task.sh` |
| **8/06 与 8/26 的原始数据已从悬空提交找回**(93 / 89 篇论文,原始 JSON 与 watchlist),并用新增的 `--render-only` 从 JSON 重渲染出缺失的 digest | `git show 27b852b:...` / `1e8d38e:...` |
| **抓取脚本新增 `--date` 与 `--render-only`**:可指定日期重跑,也可只从已有 JSON 重渲染,无需联网 | `scripts/daily_robotics_research.py` |
| **门禁会直接报出这类缺口** | `scripts/check_periodic_artifacts.py`(`daily` 检查) |
