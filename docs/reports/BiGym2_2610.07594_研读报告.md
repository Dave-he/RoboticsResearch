## 核心问题

这篇论文**不提出新方法,提出一个新的评测坐标系**。它要回答的问题有三层:

1. **现有「人形家务操作」基准测错了东西。**
   前身 BiGym(CoRL 2024,H1,40 任务)虽然提供 40 任务 + 人类 VR 演示,但其**发布的演示走的是 mobile-bimanual 模式**:浮动基座直接下发身体平移/高度/偏航增量,腿只跟随高度条件化的**运动学**轨迹。**平动上它等同于一个全向 AMR 轮式底盘** —— 也就是说,它把「移动 + 双臂操作」从「步行控制」里隔离出来了。

2. **根因:步行执行栈与操作不是可分离的两层。**
   论文的论证很硬:轮式底盘直接执行速度指令;而**行走控制器通过动态步态实现同样指令,会滞后、振荡、扰动躯干**(引 [5]–[7] 的搬运平衡研究)。G1 的足底冲击在搬运演示中实测呈现 **3.45 Hz 周期**(中位间隔 0.29 s),可以直接把夹爪里的盘子**慢慢转起来**(见 Appendix F)。**因此脱离真实执行栈来评测操作策略,测的是幻觉。**

3. **新的视角:跨范式(cross-paradigm)可靠性审计。**
   今天造机器人能力的路线有两条:
   - **数据驱动策略学习**(VLA 微调 / IL / demo-driven RL)
   - **agentic 策略开发**(coding agent 从 skill library + 环境 API 合成可执行程序)

   论文问:**这两条路线在同一套物理执行栈下,各自能可靠完成什么,在哪里分道扬镳,又在哪里一起失败?** —— 并且刻意做**cold-start 能力审计**:给 coding agent 与 online RL **完全相同的交互预算**(101,000 环境步)。

| 相同项 | 内容 |

### 关键设计 1:从「浮动基座」到「真实步态执行」

BiGym 原版给浮动基座下发 $(\delta x, \delta y, \delta z, \delta\theta)$;BiGym 2.0 把同样 4 个通道**重新解释为速度和高度参考**:

$$v_x \in [-0.35, 0.35]\ \text{m/s},\quad v_y \in [-0.25, 0.25]\ \text{m/s},\quad z_{\text{base}} \in [0.40, 1.00]\ \text{m},\quad \omega_z \in [-0.50, 0.50]\ \text{rad/s}$$

策略范围统一映射到 $[-1,1]$。14 个任务额外加第 21 维**绝对躯干 pitch** $\theta_{\text{pitch}} \in [-0.20, 0.80]$ rad(搬运盘子时 G1 会前倾躯干)。

**关键量化对比(Appendix B-A)**:把 pelvis roll/pitch **锁死**时,命令 $v_y = 0.25$ m/s 实际产生 **+0.164 m/s 横向 + 0.059 m/s 非预期前向速度**;加入被动铰链后是 **+0.1725 m/s 横向 + 0.014 m/s 前向**,对上上游自由浮动参考的 +0.180 m/s。**锁死会让 25% 的横向指令漏成前向漂移** —— 这是个小而硬的工程细节,说明连"浮动基座近似"都不成立。

### 关键设计 2:确定性重置(Reset Determinism)

这是全文**最被低估、也最该被其他 benchmark 抄走**的一点。

GR00T-WBC 适配器**跨控制步保存内部状态**,所以仅靠 seed 的 reset **不保证可复现**:

| 条件 | 配置差异 (max |Δqpos|) | 50 步后 |
|---|---|---|
| 仅 seed reset(用过 60 步的环境) | **9.5×10⁻²** | **2.1×10⁻¹** |
| 恢复控制器状态 | **逐位一致(bit-identical)** | — |

盘运输演示的开环重放实验:**从快照重放 20 次每步完全一致**;仅 seed reset 时 29 个关节角从 10⁻⁶ rad 分歧逐渐放大,**盘子最终位置相差最多 0.73 mm**,**40 次重放全部成功**。

> **这意味着:整个 benchmark 的噪声底被压到了物理下限。** 那些「±0」的 SE 才有意义。

### 关键设计 3:20 任务的场景几何适配

不是简单搬运,是**按 G1 的工作空间重排**:
- 盘子架**降低并内移**;洗碗机门/托盘场景加 **0.25 m 底座台**
- pick box:边桌 **0.50 m**、台面 **0.71 m**;默认厨房台面约 **0.85 m**;堆叠双桌 **0.70 m** 高、中心间距 **0.70 m**
- G1 身高 **1.32 m**

四个场景族:Reaching(3)/ Tabletop(5)/ Dishwasher(4)/ Kitchen counter(8)。

**成功判据是「达到的场景状态」而非积分奖励**,且**每个判据必须连续保持 1 s(50 个控制步)**。盘/杯/餐具/积木类任务中,**物体触地立即判失败**;机器人摔倒被记录但**不结束 episode**(这一条很关键 —— 说明「人形平衡失败」不直接等于「操作失败」)。

### 关键设计 4:Codex agent 的三种接口(这是真正的"方法论")

| 接口 | 观测 | 工具 | 种子上 | 定位 |
|---|---|---|---|---|
| **Strict**(主对比) | 3× **84×84** | **无相机标定 / 无深度 / 无 pixel-to-ray / 无 IK / 无特权腕位 / 无速率限制器** | 60 条演示种 | 与学习策略**完全对齐** |
| **Tool-augmented**(参考) | **640×480** | + 标定 + 投影 + **Mink 阻尼微分 IK** + 世界系腕/基座位 + 速率限制器(6 rad/s 低通) | seeds 0–199 | 量化**经典机器人工具**给代码合成的增量 |

- 每任务 **3 个独立 session**(共 27 个),**fresh session 之间不共享任何代码、技能、笔记**(cold-start)
- 允许 **NumPy / SciPy / OpenCV / Pillow + 标准库**;**禁止训练网络、拟合回归、构建演示查找表**(prompt 声明,**未做自动强制** —— 论文诚实标注了这点)
- Agent 只看**一条**人类演示(3 个同步 MP4);学习策略用 **60 条**
- 冻结程序在 **100 个 agent 从未见过的种子** 上跑,另**重复 10 个 episode 检查确定性**
- 提交的程序**运行时不调用 LLM**

## 核心公式提取

**本文是 benchmark / 评测类论文,原文未给出「核心数学公式」**(无损失函数推导、无架构公式、无定理)。原文唯一的数值方程是接触摩擦的调参链(Appendix F,Eq. 1):

$$
\mu_{\text{torsion}}=0.05:\quad 0.745\ \text{mm} \xrightarrow{\ \mu_{\text{torsion}}=0.05\ } 0.002\ \text{mm} \xrightarrow{\ \text{solref}/\text{solimp}\ } 0.000\ \text{mm} \tag{1}
$$

**含义**:步态扰动下 6 s 搬运在原始 Dex1 指垫**扭转摩擦 0.01** 时累积 **0.745 mm** 打滑(表现为盘子在夹爪里缓慢旋转);把扭转摩擦提到 **0.05** 降到 **0.002 mm**;再把指垫的约束参数换成盘子的(solref = [0.004, 1],solimp = [0.95, 0.99, 0.001])后归零。**未使用 weld 或附着约束**。

### 我们的形式化尝试(非论文原文,供后续 benchmark 设计参考)

> 以下是本报告为表达「公平性条件」所做的形式化,**不是论文中的公式**。

**1. 统一 WBC 下的归因条件**

设被测方法 $m \in \mathcal{M}$(学习策略 / coding agent),其策略为 $\pi^{(m)}$。若对所有 $m$:

$$
f_{\text{obs}}\ \text{相同},\quad \pi_{\text{wbc}}\ \text{冻结相同},\quad a \sim \Pi_{\text{action}}(a \mid o) \ \text{相同},\quad \mathcal{D}_{\text{demo}}(60 \text{ 条})\ \text{相同},\quad B(m) = B_0 = 101{,}000
$$

则评测成功率差异 $\Delta_S(m_1, m_2)$ **可归因于策略本身**,而非观测表征、控制栈、数据或预算。

**2. 结果不确定性的分解**

$$
\text{观测到的方差} = \underbrace{\sigma^2_{\text{sim}}}_{\text{控制器状态 / 物理}} + \underbrace{\sigma^2_{\text{ckpt}}}_{\text{checkpoint 选择}} + \underbrace{\sigma^2_{\text{seed}}}_{\text{3 次训练 run}} + \underbrace{\sigma^2_{\text{session}}}_{\text{agent session 间}}
$$

论文的 $\sigma^2_{\text{sim}} \approx 0$(bit-identical 重置),**并明确指出取 last-5-checkpoint 均值是为了避免用评测种子选 best-checkpoint 所引入的乐观偏差**;而 $\sigma^2_{\text{session}}$ 对 coding agent 极大(如 dishwasher close:Astra 三次 session = 100 / 0 / 0)。

**3. 「交互预算」的可比性 —— 一个真实的量纲问题**

论文自己点破了:online RL 的预算是 **interactions**,offline RL 的预算是 **updates**,"两者以不同单位计数,并如此报告"。若强行等价,则隐含假设

$$
\text{env step} \equiv \text{gradient update} \equiv \text{agent env step}
$$

在 84×84 三相机 + WBC 在环下,**每个环境步 ≈ 20 physics substeps + 3 次渲染 + 1 次 50 Hz 控制器推理**,而一次梯度更新只是几毫秒的矩阵乘。**本文用相同的 101,000 数字对齐了两者,但这个数字的真实"购买力"并不相同** —— 这是本报告对该 benchmark 最实质的方法论质疑,详见「局限性」。

- **交叉污染预警**:strict session 的 Astra body command 被放宽到 ±1.0 m/s(学习策略受演示元数据约束到 ±0.35 m/s),实测 **95% 的控制步仍在界内** —— 论文诚实披露了这点

### 5. 一个非常有意思的发现:预训练先验泄漏到「冷启动」

Claude Opus 5.5 在 **27 个 strict 程序中的 22 个**使用了与 Unitree 公开 `g1_29dof.urdf` 原始版本**五位有效数字完全吻合**的连杆偏移(例:shoulder-pitch 在躯干坐标系 $(0.0039563, 0.10022, 0.23778)$ m)。而仿真器用的是**带 Dex1 夹爪的后续修订版**,在**两个偏移上不同**(shoulder pitch z = 0.24778 m、wrist yaw 0.051 m 而非 0.046 m)。**所以这些值是从预训练里回忆的,不是从仿真器读的。**

24/27 个程序数值求解了 IK(18 个用 `scipy.optimize.least_squares`);3 个 drawer-closing session 没解。**GPT-6 Astra 无一程序含这些值、也无一解 IK。**

**但 Opus 的九任务均值(61%)与 Astra(65%)相当** —— **记忆的运学并没有消除接触密集任务上的失败**。这是一个很反直觉但很重要的结论:**冷启动的"冷"被预训练污染了,但这不重要,因为瓶颈不在运动学。**

## 局限性与未来展望

### 论文自述的局限(作者明确写出的)

1. **Agent 结果是 cold-start 基准,不是能力上限。** 每次开发都是全新 session,不携带任何其他任务的代码/技能/笔记。作者明说这是为了与"每个任务单独训练的学习策略"对齐,但也**主动指出这是"agent 开发的上限之外的地板"** —— 引用 ASPIRE 等工作指出,**累积已验证程序可改善跨任务泛化并降低合成成本**,本文没有测。这是全文最大的一块留白。
2. **Session 间方差极大。** dishwasher close:Astra 三 session = 100 / 0 / 0;drawer open:5 / 63 / 96。**三 session 均值反映的是"开发多久撞上一次能用的策略",不是能力。**
3. **全在仿真**,每机器人只有一个冻结 WBC,**只刻画了「策略 × 控制器」的联合栈**,没有物理部署。
4. **策略发的是高层基座速度与骨盆高度参考,不是关节力矩** —— 因此执行天然耦合于控制器跟踪精度与接触扰动下的姿态调节能力。**换 WBC 后的表现未知**(作者明确列为 future work)。
5. **Agent 结果依赖预训练先验。** Opus 记住了 G1 已公开的运动学;**换一台模型没记住的本体,agent 可能更差**。
6. **Prompt 层面的"禁止训练网络/回归/查找表"未做自动强制**,只在 prompt 里声明。

### 本报告阅读发现的问题

7. **「九任务均值」的选择性披露 —— 这是最大的方法论隐患。**
   20 个任务只公开 9 个的完整对比,**剩下 11 个只测了 ACT 和 CQN-AS 两个方法**(Table III)。而这 9 个任务是**作者选的**。看 Table II 的构成:9 个任务里 **5 个是「打开/关闭」类单一关节判据**(drawer close 100%、drawer open 99%),这类任务几乎不涉及平衡耦合,却**在均值里占 5/9 的权重**。剔掉 drawer close/open 后重算:

   | 口径 | π0.5 | ACT | DP | CQN-AS | DrQ-v2+ | DEAS | Opus | Astra |
   |---|---|---|---|---|---|---|---|---|
   | 九任务均值(论文口径) | 75 | 68 | 56 | 50 | 11 | 41 | 61 | 65 |
   | **去掉 2 个 drawer 任务(7 任务)** | **71** | **62** | **46** | **43** | **3** | **27** | **50** | **61** |

   **排序没变(π0.5 > ACT > Astra ≈ Opus > DP > CQN-AS > DEAS > DrQ-v2+)**,这是好消息 —— 结论对任务子集稳健。但绝对差距被单一关节任务抬高了,读者若只看"75 vs 61"会高估 agent 与 VLA 的差距。**论文没有报告这个敏感性分析,应当被追问。**

8. **π0.5 只有 1 次训练 run,却与 3-run 方法并列。**
   Table II 明确标注:π0.5 是 "one training run per task",50 episode/checkpoint,pooled over last-5。**这意味着 π0.5 的 75% 是一个点估计,没有 SE**。在 RL 领域 seed 方差众所周知可以到 ±5–10%,**π0.5 的真实均值可能显著低于 75**。**摘要里"VLA fine-tuning has the highest nine-task mean"这句话,证据强度弱于表格呈现的观感。**

9. **「101,000 交互预算」的量纲不可比 —— 论文承认但未解决。**
   原文:"The online and offline budgets are counted in different units—interactions against updates—and are reported as such."
   - CQN-AS / DrQ-v2+:101,000 **环境步**,每步一次更新
   - ACT / DP / DEAS:101,000 **梯度更新**(从不交互)
   - Coding agent:101,000 **环境步**,但 **每次 reset 收费 200 步** + episode 内步数
   - π0.5:**30k updates**(只有别人的 30%)

   **这不是同一个 101,000。** 一个 agent session 的 101,000 步里,若有 11 次 reset 就烧掉 2,200 步做重置。论文在 stacking 讨论里恰好点破了代价:"With the 101,000-step budget and an 8,750-step episode limit, trials running to completion admit only **eleven episodes**, leaving narrow margins to repair long-horizon programs." —— **长时序任务里,coding agent 的有效试错次数只有个位数到十几次,而 IL 有一万多次梯度更新。** 这个不对称性对「双物体搬运」「堆叠」这类长时序任务**系统性地不利于 coding agent**。

10. **DrQ-v2+ 的 0% 不是能力评价,是接口/探索失效。**
    Appendix F-B:在 reach target single 上 20 个 episode **全部走开工作区**,骨盆位移 **1.38–7.13 m(均值 4.20 m)**,全部超时。论文诚实写:"These rollouts show how DrQ-v2+ fails; they do not isolate the lack of action chunking as the cause." —— 但这意味着**Table II 里 demo-driven RL 的"最差基线"是谁,是超参/实现敏感的结果**。DrQ-v2+ 没有 action chunking(K=1)、没有 temporal ensembling,而它是唯一在 8/9 任务上 0% 的方法。**用一个坏掉的基线撑起"coding agent 超过所有 demo-driven RL"的论断,证据链偏弱。** 严格说,本文只稳妥地证明了 **agent > CQN-AS、> DEAS**。

11. **接触模型是被"修好"的,而非被"评测"的。**
    Appendix F-A 为了消除步态导致的夹爪打滑,调高了指垫扭转摩擦(0.01 → 0.05)并替换了约束参数。**这意味着当前数据集里的 1,200 条演示,是"调整后接触模型"的演示。** 如果这个调整本身改变了任务的物理难度(比如原本该打滑的场景变得容易),那么 benchmark 的绝对成功率就**继承了这个调参的产物**。论文说"no weld or attachment constraint is used"(这点很干净),但**接触参数校准本身作为一个基准的隐含自由度,应该在 benchmark 文档里被冻结并公示**。

12. **成功率绝对值仍远低于产线要求。**
    最好的单个非平凡任务是 drawer close / reach multi-modal 的 100%,但**多物体搬运全线塌方**:move two plates π0.5 68% / ACT 39% / DP 18% / CQN-AS 21% / Opus 15% / Astra 16%;load cutlery ACT **11%**、CQN-AS **10%**;stack blocks 全场 ≈0。**这些不是产线能用的数字。**

### 未来方向(论文提的 + 我们的推断)

**论文提的**:累积技能(skill accumulation);多 WBC 对比;world-action model;物理部署。

**我们的推断**:
- **跨 WBC 评测是下一步最有价值的实验**。本文固定 GR00T-WBC,而 policy 输出的是速度指令 —— 这层抽象让"策略"与"步态"的耦合完全没有被测。**换一个慢 1 帧的 WBC,所有排名会怎么变?** 这直接关系到"我的策略好不好"还是"我的策略适不适配这个 WBC"。
- **agent 的价值主张需要重新表述**。当前证据支持的是:"在**几何固定、判据可写、视觉伺服可行**的任务上,写程序比学策略更省。" 而在**需要物理常识**的接触任务上,工具链给回 +23 分,但绝对值仍不如 VLA 的 75。**agent 现在的正确定位不是"VLA 的替代",而是"几何/判据明确任务上的零训练开销替代"。**

## 应用与行业映射(本项目强制要求)

### 1. 应用方向

BiGym 2.0 的 20 任务精确对应四类**人形机器人的真实工况**,而且分类不是随意的:

| 场景族 | 任务数 | 产业对应 | 为什么难 |
|---|---|---|---|
| **Reaching** | 3 | 服务机器人送物、递物 | 唯一区分「选哪只手」与「双手协调」的任务族 —— 这直接对应**双工位产线**的人机协作 |
| **Tabletop** | 5 | **餐饮后厨、洗碗、摆盘** | 盘子/杯子/餐具的**连续搬运 + 姿态重定向**,最接近"擦桌子/收拾餐桌" |
| **Dishwasher** | 4 | **餐饮后厨自动化、家政** | 洗碗机门 + 托盘是**关节式夹具 + 约束放置**,是唯一有真实机械配合的 |
| **Kitchen counter** | 8 | **家庭通用、家政机器人** | 抽屉/橱柜 + 大件搬运(3 kg 箱子跨 0.50→0.71 m)+ 工具使用(锅铲铲三明治) |

**受益最大的场景**:
- **后厨/餐饮自动化**是最直接的落点(dishwasher + tabletop + put cups 共 9 个任务)。今天餐饮后厨自动化的瓶颈不是"抓",而是**开门 + 托盘 + 连续装填**这套组合动作,而这恰好是 BiGym 2.0 里 IL/RL 表现最差的一段。
- **家政整理**(叠衣、收纳、搬箱子)对应 kitchen counter 的 8 个任务。
- **双臂装配/递料**对应 reach dual —— 这是 agent 程序唯一明确领先 VLA 的地方。

**这篇论文的产业价值不在于"哪个方法最强",而在于它给出了一个可信的判定:哪些家务任务在 2026 年是可做的,哪些是研究级的。** 20 个任务的成功率表基本就是一份「人形家务机器人能力成熟度地图」。

| **真机遥操作定制** | Figure / 智元路线 | **数百~数千小时**真机 | 本论文不评 | 低 | **最高**(数据工厂) |

> **成本量级参照**:
> - **G1 整机**:约 **$16k–$30k**(教育/研究级);Dex1 夹爪另计
> - **真机人形数据采集**:业内公开量级约 **$100–500 / 小时**(遥操作员 + 场地 + 机器人折旧 + 返工);Figure 一类数据工厂路线通常年投入 **千万美元级**
> - **本文 agent 开发成本**:**$8.7–$12.1 / session / 任务**,即**一个家务任务的"程序开发"总成本在 $10–30 量级** —— 比采集 1 小时真机数据还便宜一个数量级
> - **本文仿真训练成本**:单卡 RTX 5090,**3–8 小时/任务**,硬件折旧摊薄后接近零边际成本
>
> **结论**:**对几何明确、判据可写的任务,"写程序"的成本比"采数据"低 1–2 个数量级;但绝对性能上限仍不如 VLA + 微调。** 这是 2026 年最诚实的成本-性能权衡。

### 4. 量产壁垒

**按环节拆解(标注本文提供的证据强度):**

| 环节 | 壁垒 | 本文证据 |
|---|---|---|
| **① 硬件成本** | **不是瓶颈**。G1 已降到 $16k–30k 量级,仿真训练单卡 RTX 5090 3–8 h/任务。**本体与训练算力都不再是门槛** | ✓ 强证据 |
| **② 全身控制器** | **真正的隐藏瓶颈**。本文全部结论都建立在「一个冻结的 GR00T-WBC」上,策略输出的是**速度指令而非关节力矩**。**换一个 WBC,策略可能完全失效** —— 论文自己承认没测 | ⚠️ **最大空白** |
| **③ 接触/物理建模** | **被本文绕过但没解决**。仿真里通过调指垫摩擦(0.01→0.05)+ 约束参数把步态打滑压到 0,**这是基准的人工校准产物**。真机上是真实的摩擦随机性、柔性形变、零件公差 | ⚠️ 中等证据(附录 F 反证了这个问题的存在) |
| **④ 数据** | 仿真内 60 条/任务已足够(multi-modal reach 达 90–100%);但**跨 sim2real 的数据需求量本文完全未测**。真机路线仍是数千小时量级 | ⚠️ 无 sim2real 证据 |
| **⑤ 可靠性** | **绝对成功率距产线 >90% 仍差一个数量级**。多物体搬运全线 <70%;stack blocks ≈0;load cutlery 11% | ✓ 强证据 |
| **⑥ 长时序** | **coding agent 在长时序任务上预算被 reset 吃掉**。101,000 步预算 + 8,750 步 episode 上限 ⇒ **跑完整条轨迹只够 11 次**。长程序几乎无法调试 | ✓ 强证据(论文自述) |
| **⑦ 复现/信任** | 环境、演示、轨迹全开源 ✅;但 **agent 结论是一次性快照**(session 间方差可达 100/0/0),**NVIDIA 自家 GR00T N1 未参评** | ✓ 强证据 |
| **⑧ 认证/安全** | **本文完全未涉及**。真机家用场景的 ISO/UL 认证、人机共处安全、功能安全(急停/失衡保护)一条都没测 | ✗ 无证据 |

**卡在哪一环?—— 本报告判断:卡在 ② 和 ⑤。**

② 是**架构性**的:把「策略」抽象成「基座速度 + 臂关节目标」,就把整套能力的安全性外包给了 WBC 团队。**这对产业其实是好事**(可以换 WBC 而不重训策略),但**前提是你测过换 WBC 会怎样** —— 本文没有。⑤ 是**能力性**的:双臂协调、多物体搬运、堆叠这三类,四种方法全部不及格。

### 5. 时间窗估计

**1 年内(2026–2027)**

- **benchmark 层:已经在发生了。** BiGym 2.0 的数据 + 环境 + 确定性 reset 协议会被 3–5 个团队跟进。**"用 bit-identical reset + last-5-checkpoint 均值 + 3 次 run 报 SE"应该成为 2027 年后机器人评测的默认规范** —— 这一条可能比任何具体数字都更有产业影响。
- **落地场景**:高度几何化的家务子任务 —— **开/关抽屉与橱柜、洗碗机门、递物(reach dual)**。这些在 Table II 里 ≥78% 甚至 100%。
- **coding agent 路线**:会先在**判据可形式化的仿真任务**上被采用(Gym 环境自动化求解、游戏/工具脚本化),机器人侧则是 PoC。
- **商业影响**:Figure / 宇树 / 智元 / Agility 的竞品比较将第一次有了**公开可查的横比表** —— 这会压低一部分"我们最先进"的营销空间。

**3 年内(2028–2029)**

- **双臂协调与多物体搬运**是下一个攻坚点。ROS 圈已有的 `MoveIt 2` 多约束规划 + 本文的 arm-level 策略分层(把「规划哪个物体到哪」交给符号规划器,「怎么控」交给 VLA/程序)是**最可能的落地架构**。理由就是本文的数据:**agent 在 reach dual 89% vs VLA 58%** —— 混架构已经赢了。
- **价格预期**:人形整机进一步下探到 **$10k–20k**(G1 已建立锚点),但**能干的家用型号**预计仍在 **$30k–50k**,因为**能力(不是硬件)是主要成本**。
- **coding agent + 完整工具链**很可能成为机器人策略栈的标准组件之一(本文已给 76% 均值 + $8.7/session 的证据)。
- **风险**:若 ② 的 WBC 耦合问题在 2028 年前没被跨 WBC 评测解决,整个「策略模块化」的叙事会受挫。

**5 年内(2030)**

- **多物体搬运与堆叠是否被解决,决定了家用人形是不是一个真实品类。** 本文给出的基线是 ~0%。若 2030 年这个数字还没到 50%,1X / Figure 的家用叙事需要重新定价。
- **Agent 范式的终局形态**:本文的结论指向一个混合架构 —— **agent 负责把任务编译成几何/约束层的可执行程序,学习模型负责难以形式化的接触与泛化部分**。纯端到端 VLA 与纯代码合成都不会是终局;**本文是支持这个混合架构最硬的公开证据之一**。
- **颠覆性**:如果「agent 写程序 + 冻结 WBC」真的能覆盖大部分家务任务,那么**机器人能力的边际成本将从「小时级真机数据」降到「美元级 API 调用」**,数据采集产业的规模会大幅萎缩。这是本文最深远的产业含义。

## 横向对比:四类被测方法的定性对比

> 基于 Table II / III / IV 与 Appendix D 的综合判断。评分为本报告的定性归纳,非论文原文。

| 维度 | **IL**<br>(ACT / DP) | **Demo-driven RL**<br>(CQN-AS / DrQ-v2+ / DEAS) | **VLA fine-tuning**<br>(π0.5) | **Coding agent**<br>(Opus 5.5 / Astra) |
|---|---|---|---|---|
| **数据需求** | **60 条演示**,最低 | 60 条演示 **+ 101k 环境步交互** | 60 条演示 **+ 强预训练底座**(π0.5 权重,需许可) | **1 条演示** + 环境 API 文档(最低) |
| **训练/开发成本** | 单卡 RTX 5090,**5.9–7.9 h/任务** | 同硬件 + 交互成本,**3.3–5.3 h/任务** | 30k updates(**别人的 30% 预算**) | **$8.7–$12.1/session**,GPU 占用为开发期而非训练期 |
| **样本效率** | 中 | **低**(需大量交互;DrQ-v2+ 甚至走离工作区) | **高**(预训练先验强,60 条即可;Opus 还额外**回忆了 G1 运动学**) | **极高**(但从"训练"角度看是零学习) |
| **跨任务泛化** | **零**(每任务独立训练;cold-start) | **零** | **名义上有**(多模态预训练),但本文是**每任务独立微调**,实测无跨任务收益证据 | **本文为设计所限的零**(作者明说:这是 cold-start 地板,非能力上限;技能累积未测) |
| **可解释性** | **中**(动作 chunk 可视) | 中(价值函数可查) | **低**(纯黑箱,3B 级 VLM) | **最高**(程序可读可审、可手改、可版本控制;**可审计 = 可用于安全场景**) |
| **几何/夹具任务**<br>(drawer, dishwasher) | 中–高 | 中 | **高** | strict 弱 / **tools 后极强**(dishwasher +67) |
| **双臂协调**<br>(reach dual) | **弱**(30 / 27) | **极弱**(3 / 0) | 中(58) | **最强**(78 / 89) |
| **多物体搬运**<br>(move 2 plates) | **弱**(39 / 18) | **弱**(21 / 0 / 2) | **最强**(68) | **弱**(15 / 16) |
| **长时序**br>(stack blocks) | **~0%** | ~0% | 未评测 | **19% / 0% / 0%**(最好的一次 session) |
| **开源成本 / 门槛** | **最低**(ResNet-18 + 一张 5090) | 中(需实现 3 个 RL 算法 + 超参对齐) | **高**(需 π0.5 权重与许可;30k 更新) | **中等**(需 agent harness + API 额度 ≈ $560 跑完全部实验) |
| **确定性 / 可复现** | 高(固定超参可复现) | 高 | **低**(单 run,无 SE 估计) | **低**(session 间方差可达 100/0/0;冻结程序高) |
| **规模化路径** | 加数据/加任务即可 | 交互成本线性增长 | 加底座规模 | **加工具链(+23 分,已验证)** / **加技能累积(未测,论文认定的关键缺口)** |

**一句话总结**:
> **VLA fine-tuning 拿下了「有足够先验时的最高均值」;IL 是最便宜的起点;demo-driven RL 在这个执行栈上性价比最差(101k 交互只买到 50%);coding agent 拿下了「双臂协调 + 可审计」,而它最大的武器(经典机器人工具,+$23)恰恰是它最容易被低估的资产。**
