## 核心问题

这是四篇里**问题陈述最锋利**的一篇。它指出了当前人形 VLA 的一个结构性盲点:

### 现有范式的两层断裂

```
语言/视觉 → VLA → 【几何运动目标】 → WBC(运动跟踪) → 关节力矩
                          ▲                          ▲
                    只管几何                 只管跟踪
```

**断裂 1 —— VLA 与 WBC 之间丢失了"力"这个自由度**

现有系统里,VLA 输出的动作被表示为**几何运动目标**(末端位姿 / 关节参考),WBC 被设计为**运动跟踪器**。于是"用多大力气"这个决策**在接口处根本不存在** —— 没有任何地方能表达它。

论文的论证是:**在接触密集任务中,几何上完全相同的运动,在不同任务语境下需要不同的力调节**。

举例:同样是"把杯子举到嘴边"
- 空杯 → 轻力,防碎
- 装满水 → 大力,防洒
- 递给别人 → 中力,防失手

**三条指令的末端几何轨迹可以完全一致**,差别只在力。若 VLA 只能输出几何,这三种情况在策略看来是**同一个动作**。这是**信息在接口处的结构性丢失**,不是模型容量问题。

**断裂 2 —— 接触后视觉失效**

> "visual observations may become unreliable after contact"

这是被严重低估的一点。接触一旦发生,视觉观测立即退化:
- 物体遮挡手指 / 末端
- 快速运动 → 运动模糊
- 接触形变 → 视觉与实际接触状态脱节

而**恰恰是接触之后的阶段,最需要精细的力调节**。视觉在关键窗口失效,却仍是唯一的主要反馈通道 —— 论文由此论证必须有**非视觉的显式力通道**。

> 这两个论点合起来构成一个闭环论证:**力既是决策变量(因为语境相关),又是必要的反馈通道(因为视觉会失效)。** 这是比"力控有用"强得多的主张。

## 方法论与核心思路

### 三层架构

```
┌────────────────────────────────────────────────────────────┐
│  ①  单体多任务 VLA 策略  (single multi-task VLA)            │
│     输入: 视觉 + 语言                                      │
│     输出: ┌──────────────────┬────────────────────────┐    │
│           │ 几何运动目标      │ 连续接触力参考 f*        │    │
│           │ (geometric goal)  │ (continuous force ref) │    │
│           └──────────────────┴────────────────────────┘    │
│                            ↓ 同时输出                       │
├────────────────────────────────────────────────────────────┤
│  ②  任务专属 RL 全身控制器 (task-specific RL-based WBC)     │
│     同时跟踪: 几何运动目标 + 力参考                          │
│     输出: 全身关节力矩 τ                                    │
├────────────────────────────────────────────────────────────┤
│  ③  物理可行的训练数据生成                                   │
│     全身轨迹优化 (TO) + 显式力参考                            │
│     → 产出"动力学可行 + 接触一致"的监督信号                   │
└────────────────────────────────────────────────────────────┘
```

### 关键设计 1:显式力命令放在 VLA→控制接口

这是标题里 "Opt2VLA" 的含义 —— **力成为接口上的一等公民**,而非隐藏在控制器内部:

$$
\big(\underbrace{g_{\text{geo}},\, f^*_{\text{contact}}}_{\text{VLA 双输出}}\big) \;\longrightarrow\; \underbrace{\pi^{\text{WBC}}_\phi(\text{state}, g_{\text{geo}}, f^*_{\text{contact}})}_{\text{RL 全身控制器}} \;\longrightarrow\; \tau
$$

与主流做法的关键差异:

| 维度 | 现有 humanoid VLA | **Opt2VLA** |
|---|---|---|
| VLA 输出 | 几何运动目标 | **几何 + 连续力参考(联合)** |
| 力从哪来 | WBC 内部阻抗/导纳**隐式**决定 | **VLA 显式给出** |
| 力能否按语言调 | ❌ 语言只能改几何 | ✅ **"轻一点拿" / "用力压"** |
| 视觉失效后 | 只能靠几何猜 | 力参考**不依赖视觉** |

最后一行是这套架构的**真正杀手锏**:力参考是**在接触发生前(视觉还可靠时)算出来的**,可以在接触后继续作为有效反馈。视觉掉了,力通道还在。

### 关键设计 2:TO 生成物理可解释的力监督

力参考从哪来?直接从人手演示里回归出力,会有严重的**物理不可行**问题(人手动力学 ≠ 人形动力学,很多力模式人根本做不到)。

Opt2VLA 的做法是用**全身轨迹优化(Trajectory Optimization)**反向生成监督数据:

```
人形 URDF + 接触约束 + 物理可行动力学
        ↓ TO 求解
   带显式力参考的全身轨迹
        ↓
  物理可行的力监督信号
```

摘要强调了两个词的组合:**"dynamically feasible"** + **"contact-consistent"**。即 TO 产出的不只是"看起来对"的轨迹,而是**在人形自身动力学与接触约束下真的可执行**的力序列。

这解决了力数据采集的经典死结:**力标签比位姿标签难采得多,且噪声大**。用 TO 合成绕开了这个问题。

### 关键设计 3:任务专属 RL WBC

不是单一通用控制器,而是**每个任务一个 RL WBC**。这带来一个务实的取舍:

- ✅ 力跟踪精度高、可专门优化
- ❌ **每个新任务都要训一个新 WBC** —— 这是部署上的真实成本,VLA 的"通用性"被 WBC 的"专用性"抵消了一部分

摘要未说明 WBC 是 per-task 独立训练还是多任务共享(只说 "task-specific")。若确为 per-task,则整个系统的通用性上限由 WBC 覆盖的任务数决定。

## 核心公式提取

**论文全文未获取**,以下为依据摘要的**结构性示意**,非论文原式:

**1. VLA 的联合预测目标**

$$
\pi_\theta\!\left(o_t,\, l \right) \;\longrightarrow\; \left( g_t^{\text{geo}},\; f_t^{*} \right)
$$

其中 $o_t$ 为视觉观测,$l$ 为语言指令,$g^{\text{geo}}$ 为几何运动目标,$f^{*}$ 为连续接触力参考。二者由**单个多任务策略联合输出**。

**2. RL WBC 的力跟踪奖励**(结构示意)

$$
r_t = w_g \underbrace{\mathcal{L}(g_t^{\text{geo}}, \hat{g}_t)}_{\text{运动跟踪}} \;+\; w_f \underbrace{\big\| f_t^{*} - \hat{f}_t \big\|}_{\text{力跟踪}} \;+\; w_s \underbrace{\mathcal{L}_{\text{stab}}}_{\text{稳定性}}
$$

**3. TO 监督的物理可行性约束**(结构示意)

$$
\max_{\{q_t,\, f_t,\, \lambda_t\}} \; \mathcal{J}_{\text{task}}
\quad \text{s.t.} \quad
\underbrace{M(q_t)\ddot q_t + h(q_t,\dot q_t) = S^\top \tau + J_c(q_t)^\top \lambda_t}_{\text{动力学可行性}},
\quad \underbrace{g(q_{c,t}) \ge 0}_{\text{接触一致性}}
$$

$\lambda_t$ 为接触力(拉格朗日乘子),这正是 TO 天然能给出**物理可行力**的原因 —— 它是约束的乘子,而非事后拟合的量。**这一点很可能是本文方法论的精髓**:TO 里的接触约束乘子 $\lambda$ **直接就是**要监督 VLA 输出的力参考。

## 关键成果与贡献

摘要披露的三条结论(均为定性,**未给数字**):

| # | 结论 | 意义 |
|---|---|---|
| 1 | **显式力条件**比**仅运动(motion-only)**在力调节上"更准确、更一致" | 验证了核心假设 |
| 2 | **来自 TO 的物理可行力矩监督**进一步提升力跟踪精度与稳定性 | 验证了数据生成方式的价值 |
| 3 | **闭环语言条件化力调制**在**仿真与真机人形硬件**上均实现 | 端到端可用性 |

**诚实的评估**:三条结论都是"更好 / 进一步提升"的定性表述,**摘要一个数字都没给**。而论文体量 27 MB 说明有大量实拍视频 —— 但 video 数量不等于定量证据。

**方法论贡献的实质**:这篇的贡献不在某个模型结构,而在于**重新定义了 humanoid VLA 的动作接口**。把力从"控制器内部的自适应行为"提升为"策略的显式输出",是一个**接口层的设计决策**,这个决策可被后续工作继承(换底座 VLA、换 WBC 都可复用)。相比之下 VisForce 把力塞进图像(表示层),Opt2VLA 把它放在接口上(接口层)—— 见 §横向对比。

## 局限性与未来展望

**摘要/元数据层面的局限**:

1. **零定量数字**。三条结论全为定性。作为对比,VisForce 至少报了 40–80%。**这是本报告最大的证据缺口**
2. **三个任务未命名**。摘要只说 "three contact-rich humanoid tasks",完全没说是什么 —— 无法判断难度与代表性
3. **无项目页、无代码**。**无法评估可复现性**
4. **未说明真机型号**。哪个平台?自研?还是 Unitree / Fourier?
5. **未说明底座 VLA**。7B? 3B? 自研? 这直接决定部署成本

**我们阅读发现的技术疑虑**:

- **"task-specific WBC"是部署陷阱**。如果每个任务一个 WBC,那新增任务 = 新增一次 RL 训练。系统通用性被 WBC 的专用性卡住。摘要未说明是否多任务共享
- **力的时序对齐问题**。VLA 以多低频率运行?WBC 以多高频率运行?VLA 输出的 $f^{*}$ 在两次 VLA 推理之间如何插值?接触瞬间的力突变如何处理?摘要完全未提,但这是**工程上最容易崩的地方**
- **视觉失效的解法其实不完整**。论文论证了"接触后视觉不可靠",但**只给了力这一条非视觉通道**。接触状态(是否已贴合、有没有滑移)仍无解 —— 力是必要不充分的
- **TO → sim → real 的 gap**。TO 在仿真里跑,人形的动力学参数、接触摩擦、电机饱和都可能有偏差。摘要说"physically grounded"缓解了这点,但**没有量化 gap**
- **"opt" 二字的来源未解释**。标题 Opt2VLA 中的 "Opt" 大概指 trajectory optimization,但也可能指其他含义,需查 PDF

## 应用与行业映射(本项目强制要求)

### 1. 应用方向

论文定位是**接触密集型人形全身操控**,对应的产业场景:

- **装配 / 制造**:插接、拧紧、压装 —— 典型的几何相同但力不同
- **搬运易碎 / 柔性物**:同样是搬运轨迹,轻重不同
- **服务机器人**:开门、递物、扶扶 —— 家庭与商场的通用需求
- **核心价值**:**让"用多大力"成为可被语言指定的能力**("小心点拿" / "使劲")

### 2. 行业玩家

| 厂商 / 方向 | 现有方案 | 本方法的介入方式 |
|---|---|---|
| **Physical Intelligence(π0/π0.5)** | 通用 VLA,输出动作序列,力/触觉多为附加通道 | **接口层范式可直接被 PI 采纳** —— 改输出头即可,底座不动 |
| **Figure AI** | Helix 双系统 VLA,力控主要在 WBC 内部 | 若显式力指令有效,Helix 可增设力输出头 |
| **1X Technologies** | 类人,强调家庭场景 | 家庭接触任务多,力调节收益大 |
| **Tesla(Optimus)** | FSD 风格 end-to-end,关节力矩端到端 | 路线不同(end-to-end 无显式接口),但力作为中间变量是可控性 trade-off |
| **Unitree / Fourier / 智元** | 平台厂商 + 自研控制器 | 可作为 WBC 供应方,承接 Opt2VLA 的接口约定 |
| **力传感器厂商**(ATI、坤维等) | 六维力/关节力矩传感 | 显式力参考**不能省掉力传感**,利好传感器需求 |
| **WBC 厂商 / 全身控制框架** | 提供控制器 | 接口层约定若成标准,可能催生生态 |

### 3. 替代方案对比

| 方案 | 力能否被语言指定 | 接触后反馈 | 通用性 | 成熟度 |
|---|---|---|---|---|
| 运动目标 + 阻抗 WBC(主流) | ❌ 力由控制器内部自适应 | 靠本体力矩 | 较好 | **工程成熟** |
| End-to-end 力矩输出 | ⚠️ 隐式,难指定 | 直接 | 好 | 训练代价高 |
| 视触觉传感器 + VLA | ⚠️ 间接 | 视觉退化时也退化 | 中 | 硬件贵 |
| **Opt2VLA 显式力接口** | ✅ **直接** | **力通道独立于视觉** | **受 task-specific WBC 限制** | **早期研究** |
| VisForce 渲染式(见对照报告) | ⚠️ 目标图间接 | 力渲染在图像上 | 中 | 早期研究 |

### 4. 成本结构推演

摘要未给成本。按架构推断:

**降低的成本**:
- 训练数据由 TO 合成,**省掉大规模真机力数据采集** —— 这是真金白银的成本项
- 力监督物理可行,**减少 sim2real 微调轮次**

**增加的成本**:
- **多一套 RL WBC 的训练与部署** —— 每个任务一份,人力与算力双重成本
- **VLA 输出头扩张** —— 需要额外的力预测分支
- **力传感器仍是硬需求** —— 与 VisForce 一样,显式力参考不能脱离真实力反馈
- **推理调度复杂** —— 异频 VLA/WBC 的时序同步

**量产卡点**:

| 环节 | 卡点 |
|---|---|
| **task-specific WBC** | **最大商业卡点** —— 通用性叙事被"每任务一控制器"抵消;若无法多任务共享,落地成本随任务数线性增长 |
| **VLA 底座不公开** | 无法评估集成成本与延迟预算 |
| **无代码** | 工业界无法做 PoC |
| **力传感 BOM** | 人形全身力矩反馈本身成本高,显式力参考不降本 |
| **时序同步** | 异频控制器的工程稳定性,论文未披露,是隐性风险 |
| **接触状态缺失** | 只有力,没有"是否接触/滑移"的显式状态,极端场景可能失稳 |

### 5. 时间窗估计

- **1 年内(2026-2027)**:学术圈跟进,力作为 VLA 输出维度会成为**可选设计**;底座 VLA 若开源(PI 系倾向开源),社区会快速复现
- **3 年内(2028-2029)**:若 task-specific WBC 的多任务化取得突破,可能进入**装配 / 3C 制造试点**;该场景对力调节需求最刚
- **5 年内(2030)**:力作为 VLA 显式输出维度,若被 π0 类底座采纳,可能成为**行业事实标准接口** —— 这是最乐观也最有杠杆的路径

### 6. 战略判断

**这是今天四篇里最值得持续跟踪的一篇**,理由不是它跑出了多高的成功率,而是:

1. **问题陈述锋利且正确** —— "几何相同但力不同"和"接触后视觉失效"这两条,确实是当前 humanoid VLA 的真问题
2. **接口层设计可继承** —— 换任何 VLA 底座、任何 WBC,这个设计都能复用,杠杆很大
3. **TO 合成监督**规避了力数据采集这个最贵的环节,工程可行性高

**风险**:无代码、零数字、task-specific WBC 的通用性陷阱。**这是一篇"设计思路可信、证据尚缺"的论文**,定位与 VisForce 类似(想法好、证据不足),但**问题陈述的锐度和方法的杠杆都明显更强**。

## 横向对比:力感知 VLA 的两条路线

今天入册的两篇力感知论文构成一组极有价值的对照:

| 维度 | **Opt2VLA** | **VisForce** |
|---|---|---|
| **力放在哪一层** | **接口层**(VLA→WBC 显式输出) | **表示层**(渲染进图像像素) |
| **力如何到达网络** | 独立的连续输出头 | 叠在图像上,经视觉编码器 |
| **对现成视觉通路的改动** | 需改输出头 | **零改动**(纯输入预处理) |
| **接触后是否仍有效** | ✅ **独立于视觉** | ⚠️ 仍经视觉通路,受退化影响 |
| **空间对应** | 不适用(全身力矩) | 显式(画在指尖位置) |
| **可解释性** | 中(数值可读) | **高(直接可视化) |
| **空间 / 载体** | 人形全身 | UR10 桌面灵巧手 |
| **数据来源** | **TO 合成(物理可行)** | 摘要未说明(需真机演示) |
| **定量数字** | **未披露** | 40–80% |
| **代码** | 无 | 无 |
| **最大隐忧** | task-specific WBC 通用性 | 成功率偏低 + 无 baseline |

**综合判断**:
- 若追求**通用性与人形落地** → Opt2VLA 的接口层范式更可扩展
- 若追求**最小改动与可解释性** → VisForce 的表示层更轻量
- 二者**不冲突**,可叠加(接口层给出力信号,表示层把力可视化给人类看)
