## 核心问题

**这篇论文不提出新策略,提出的是一把「尺子」。** 它要回答的问题有三层,且第三层是全文最有价值的部分:

**1. 现有灵巧操控基准测不出「可靠」这件事。**
论文的诊断性开场句是:灵巧操作的核心不是把物体移到某处,而是**控制接触在操作过程中如何变化**——移动鼠标时不能触发提前点击;拧两个旋钮时两个旋钮必须**同时**保持在目标角度;盖盖子时必须在释放的同时保住对齐。现有灵巧基准(DexJoCo / DexVerse / Bench2Dex / LabDex)虽然拓宽了任务与本体覆盖,但**人类演示集规模小、几乎没有「只用于评测、不用于训练」的留出任务**。因此,一个方法可以在「抓得住」的维度上刷高分,同时在「接触角色分不清、双手时序对不上、已达成的目标守不住」上完全失分,而基准无从分辨。

**2. 论文认为根因是「评测坐标系的缺失」,不是「策略不够强」。**
论文的判断是:在一个「成功率二值 + 任务都是见过的」的评测体系里,失败原因被平均掉了,而**失败发生的位置(哪个接触、哪一步、哪一只手)才是可工程化的信息**。所以本文的全部设计围绕一件事——**把失败定位到具体的「手部转移点」**,而不是给出一个更高的成功率数字。

**3. 论文提出的新视角:一个「双套件 + 阶段诊断」的评测坐标系。**
- **Core-50 / Transfer-16 双套件分离**:Core-50 有演示、测「有训练支撑时的执行能力」;Transfer-16 **完全不给目标任务演示**,测「资产/关系迁移、技能组合、形变操控」,两者的分数**全程分列报告、不可相加**。
- **阶段级原生检查器**:每个任务有独立的「原生成功谓词」与**有序进度 (ordered progress)**,使得在成功率为 0 的任务上仍能区分方法好坏。
- **诊断落到三个转移点**:失败被归到「接触建立 → 动作协调 → 维持已达目标」三个转移,组合任务再加第四类「步骤时序错误」。
- **一次提示式 VLM 对照实验**:把 GPT-6 接入 `move_eef` 这个「掌心 + 手指」接口,做 660 次零样本试验,回答「通用 VLM 到底能不能直接操控灵巧手」。

> **本报告的判断**:这篇论文真正的贡献**不是 18,000 条演示**(数据量是工程量,不是方法量),而是**「把灵巧操作的失败拆成可归因的阶段」这一整套协议**。这套协议可以独立于本文的数据集,被任何做灵巧手评测的团队拿去用。反过来,**「通用灵巧操控」这个概念在本论文的证据下仍不成立**——29.1% 的最优多任务成功率说明的是「基准的分辨力被建立起来了」,不是「能力被解决了」。

## 方法论与核心思路

### 3.1 整体框架:一个「可组合 (composable)」的三层平台

HandsOn 的结构是 **任务层 / 资产层 / 本体层** 三层解耦:

```
任务层  T_i = (E_i, p_i(s_0), O_i, A_i, G_i, H_i)      ← 环境/初始分布/观测/动作/成功谓词/时间预算
   ↓ 独立于
资产层  ~200 个刚性 / 带关节 / 形变资产 + 场景随机化
   ↓ 独立于
本体层  机械臂(5 种) × 灵巧手(6 种) × 物理后端(PhysX / Newton)
```

论文的核心主张是:**换一个机械臂、换一只手、换一个物理后端,任务定义、成功谓词、演示集合都应当原样存活**。因此「跨本体」在这个基准里不是一个要验证的能力主张,而是**架构前提**——§4.6 明确列出了 KUKA / UR / ABB / FANUC 机械臂、第一代与第二代 Wuji Hand、Sharpa Hand,以及 PhysX 与 Newton 两个物理后端的可替换性。

⚠️ **但论文同时明确承认(§4.6 末段)**:所有报告的实验**只用了 ROKAE AR5-08 + 第一代 Wuji Hand + PhysX 这一套配置**;其余组合「受平台支持,是研究跨本体迁移的自然基础,但它们没有为本文结果贡献任何 episode,**论文里的数字不应被读作这些配置上的性能**」。这是本报告认为全文**最被低估、也最容易被引用者忽略**的一句限定。

### 3.2 关键创新一:Core-50 与 Transfer-16 的划分逻辑

| 维度 | **Core-50** | **Transfer-16** |
|---|---|---|
| 用途 | 策略学习 + 执行能力评测 | **仅**用于泛化评测 |
| 任务数 | 50 | 16(6 EVAL-Comb + 7 EVAL-Gen + 3 EVAL-Flex) |
| 演示 | 每任务 **46–463 条训练轨迹**(中位 268) | **不用于训练**;13 个任务使用「时长代理」,3 个 Flex 任务保留原生预算 |
| 覆盖 | 功能性工具使用、数值与空间锚定、铰接/平移部件、双手执行 | 新资产关系、技能组合、**3 个形变交互(数据集内零形变演示)** |
| 计分 | 任务宏平均成功率 | 任务宏平均成功率 + 有序进度(仅训练型方法);GPT-6 只报成功率 |
| 本质差异 | **「见过 → 做对」** | **「没见过 → 泛化」** |

**划分逻辑的关键设计(§3.1 / 附录 B.3)**:
- Transfer-16 不是随机留出,而是**沿三个正交的泛化轴**构造:**资产与关系迁移**(用熟悉技能配新物体/新组合/新目标关系)、**技能迁移与组合**(把训练过的原子技能放进新序列,例如 `Open Laptop and Click Mouse` = 开铰接件 + 操作界面)、**形变操控迁移**(`Compress Sponge into Mug` / `Fold Towel Twice` / `Pack Pillow`)。
- 论文明确区分了**「未见过的原子操作」**与**「已训练技能的新组合」**,也区分了**「熟悉资产的未见组合」**与**「新实例/新类别」**——判定依据是**源任务与资产身份**,不是任务名字。
- ⚠️ 论文自陈的边界:「这三个实现分组支持互补的泛化问题,而**不是一组完美正交的因子**」;把形变作为因果变量隔离出来还需要匹配的几何与目标。

**为什么这个划分是本论文最有价值的部分?** 因为它把「泛化」从一个形容词变成了**三个可分别记账的账本**。以往基准把「资产换了」和「技能换了」混在一起报一个数,导致「泛化能力」无法归因。HandsOn 把它拆开了——而且代价是:Transfer-16 的成功率极低(所有训练型检查点在三族上成功都接近 0),论文因此改用**有序进度**排序,这是一个诚实但也更难解读的指标。

### 3.3 关键创新二:评估协议 —— 四个层次的设计

**(a) 时间预算:由专家 P75 派生,而不是拍脑袋定**

$$
q_i = F_{i,(\min(n_i-1,\ \lfloor 0.75\,n_i\rfloor))},\qquad H_i = \frac{3q_i}{30},\qquad B_i = \lceil 30 H_i \rceil
$$

- $F_{i,(k)}$:任务 $i$ 的演示帧数序列(帧),按升序排列、零基索引
- $q_i$:该任务的**非插值 75 分位**帧长(专家 P75)
- $H_i$:**物理秒**预算 = 3 倍 P75 秒数
- $B_i$:**最大可执行动作数** = $\lceil 30 H_i \rceil$

关键细节:演示以 30 fps 录制,评测每动作推进恰好 1/30 s(由物理步长与 substep 核验);**推理延迟、渲染时间、动作块长度都不能重新定义这个物理预算**;冻结的时长表由**策展包(含其轨迹验证分区)**计算,**完全不使用被评测策略的结果**——这是一条重要的防泄漏设计。

Transfer-16 的 13 个任务没有目标任务的演示分布,改用**时长代理**:$H_i = 3\sum_{j\in\mathcal{S}_i} q_j / 30$,其中 $\mathcal{S}_i$ 是预先声明的支撑原子任务映射。论文举例 `Open Laptop and Click Mouse` 用 $(196+125)$ 源帧 → **32.1 s / 963 个动作**。三个 Flex 任务保留显式原生预算:**海绵压缩 240 s、毛巾折叠 180 s、枕头打包 180 s**。

**(b) 停止与成功判定**
每个动作执行后,原生环境检查成功 / 任务定义失败 / 超时;**在第一个终止结果处停止,即使终止发生在一个动作块内部**,未用完的预测动作被丢弃。成功要求**完整的原生谓词**,包含任何释放、稳定性或停留要求。**在最后一个允许动作上达成的成功也被接受**。没有通用的「看起来停滞就早停」或「完成中间阶段就算」的早停规则。任务特有的不可逆违规保留其原生规则。

**(c) 有效性与归因**
无效策略输出(如非有限动作)记为**该适配器下的策略失败**;仿真器缺陷、被拒绝的 reset、进程中断、基础设施故障**分别记录,不折算成数值上的策略失败**。结果保留已执行步数、物理时间、终止原因、有效性、协议版本;**历史上在更长预算下的成功,永不重新标记为较短预算下的成功**。

**(d) 诊断与统计报告**
- 主分数:逐任务成功率 + 声明任务集上的宏平均
- **有序进度**:$P_e = L_e / K_i$,其中 $L_e$ 是 episode $e$ 中完成的**最长有效有序前缀**的阶段数,$K_i$ 是任务 $i$ 的阶段数。阶段按语义操作定义——**仅仅靠近或碰到物体不算完成一个功能阶段**。进度**永不覆盖**最终成功谓词。
- 能力专项诊断:功能完成**把「拿到工具」与「操作工具」分开**;稳定性度量包括掉落、滑移、另一只手支撑下的位移;形变任务另报几何进度;**指令幅值永远不被当作实测力**。
- 不确定性:二值成功用 **Wilson 区间**;聚合不确定性的**重采样单位被显式指定**;缺失或环境无效的试验不算数值失败;每个聚合都标明任务与试验覆盖。

**(e) 试次与不确定性**
训练型检查点:**100 次/任务/检查点**(HY-Embodied 在 Place Wine Glass 上 99 次,一个 episode 无效)。GPT-6:**10 次/任务**(因 API 成本与墙钟评测时间约束)。独立评测种子在兼容的模型比较间共享。论文自陈:Core-50 上有 6 个任务的**逐任务信噪比低于 1**(跨检查点的成功率跨度 / 二项标准误),14 个任务 ≥ 3;**50 任务宏分数的 episode-only 95% 半宽在 25 / 50 / 100 次每任务时分别约为 1.9 / 1.3 / 0.9 个百分点**。

### 3.4 关键创新三:数据平台 —— 18,000 条「策展过」的人工演示

**(a) 采集系统**:Isaac Sim 5.1 → MANUS Prime I 手套 + HTC VIVE Tracker → 帧配准与时间对齐 → 腕部运动与掌心 21 关键点 → 机械臂分支经机器人运动学生成可行的末端目标,手部分支经 Wuji retargeting 映射为 20 路关节目标 → 仿真记录同步观测、实测状态、指令动作、语言与源元数据。

**(b) 数据集构成与身份(计数单位被刻意分开,这是本论文的会计纪律)**

| 计数单位 | 数量 |
|---|---|
| 策展演示轨迹 | **18,000** |
| 训练 / 验证轨迹 | **15,178 / 2,822** |
| 录制时间步 | **6,053,555** |
| 相机视频(每轨迹 3 个) | **54,000** |
| 原生任务身份 / 配额组 | **54 / 52** |

> 论文明确警告:**54,000 个视频是同 18,000 次交互的三个视角,不是三倍数据**;去重与策展之前的原始采集量**不是任何 checkpoint 的训练规模**。策展规则是**任务组配额 500 / 300 / 100 条**,并在配额内**优先选较短的合格演示**——所以这是**策展分布,不是全部采集行为的无偏样本**。一个多阶段源任务的三个阶段共享一个配额,故 54 个原生身份只对应 52 个配额组。跨包中位轨迹长度 **262 步**(10–90 分位 96–705);每个 Core-50 任务训练轨迹 **46–463 条**(中位 268),专家 P75 **2.5–49.2 s**(中位 12.7 s)。摘要给出的交互总量为**约 56 小时、三路同步视角**,并声称这是代表性灵巧基准**人类轨迹数的 5.7–16.4 倍**。

**(c) 高保真重渲染**:最终包采集每像素 **32 samples**;已实现的变异库含 **4 种桌面材质、3 种背景配置、3 种天花板样式**,叠加纹理尺度与朝向、表面粗糙度与色调、光照方向/强度/色温;一个已验证的源相机配置在**每条轨迹内**以 **±2 mm 平移、每轴 ±0.3° 旋转**采样一次,保留内参。**外观按轨迹采样并在回放期间固定**;逐帧重采样外观不在这个静态域协议内。

论文还给出一张**「什么变异必须保留什么」的准入表**(Table 4)——这是本报告认为被低估的设计:

| 变异因子 | 必须保留 |
|---|---|

**(d) 语言库与提示采样**:冻结语言库含 **108 条任务–指令条目**,其中 **91 条**出现在最终 18,000 轨迹清单里;每个活跃条目有 **32 条训练释义 + 8 条留出释义**,合计 **2,912 训练 + 728 留出释义**。参考训练混合为 **20% 规范句 + 80% 训练释义**;留出字符串与任何活跃规范句/训练句**无精确重叠**(词面不相交检查)。⚠️ 论文明确:把 apple 换成 banana、改旋钮角度、改操作顺序**不是释义**,而是需要对应可执行目标的新 episode,因此属于**任务变异而非语言变异**。

**(f) 跨臂/跨手/跨物理后端的可移植性**:见 §3.1 的架构说明与 §4.6 的限定。

### 3.5 关键创新四:`move_eef` —— 一个「掌心 + 手指」的极简接口

`move_eef` 是本文给 GPT-6 的**唯一**可调用函数,也是全文方法论上最有迁移价值的设计:

- **输入**:世界坐标位置 `xyz`(米)、绝对外参欧拉姿态 `rpy_deg`(度)、**20 个绝对关节目标** `joints_rad`。关节顺序为**拇指/食指/中指/无名指/小指,每指 4 个**。
- **省略语义**:省略掌心目标 = **保持实测位姿**;省略手指目标 = **保持上一次指令设定点**——这个设计显式保留了「已握住的命令姿态,即使接触导致无法到位」。
- **禁止项**:**没有标量夹爪命令,没有任务特定抓取原语**;非活动臂不可被指令。
- **运动学生成**:只读运动学规划器构造臂路点,每个规划步**最多 0.03 rad**(且受更严的原生限位约束);手指目标走**五次插值**,每步最多走关节量程的 **0.18**。臂与手指共享同一调度。论文明确声明:**这些是命令生成约定,不是实测速度、碰撞间隙或目标到位的保证**;规划器**没有障碍物模型**。
- **动作维度**:每个 **52 维**双手动作(每侧掌心位置 3 + 旋转矢量 3 + 20 关节目标)经基准解码器与任务原生执行器下发,保留原生控制器与物理驱动行为。
- **时间与预算**:每个执行动作推进物理时间 **1/30 s**;**一个 `move_eef` 调度上限 300 个动作(10 物理秒)**,更长的计划在执行前被拒;no-op 也消耗 1 个动作;格式错误或不可行的调用**会收到反馈但不推进物理,且仍然消耗模型调用**;原生终止可以打断调度。**API 延迟不推进仿真,也不意味着实时执行**。
- **上下文**:控制器保留**最近两个观测轮次**的全部三视角图像;紧凑上下文配置会汇总已执行步数、物理时长、执行状态,去重执行反馈,把模型可见数值状态**四舍五入到 4 位小数**;全精度仿真状态、动作、响应与执行诊断**保留用于核验**。
- **调用预算**:最终配置**每次试验允许 100 次计数模型调用**;无效/不可行调用消耗预算但不推进物理。⚠️ 论文自陈:最终批次**保留了早期已完成运行的记录设置,其中一些使用完整文本反馈或超过 100 次调用**——因此 660 次试验结果描述的是**一个固定评测总体在其记录预算下的表现,不是一次受控的紧凑上下文或统一 100 次调用的消融**。

## 核心公式提取

### 公式 1:物理时间预算(专家 P75 派生)

$$
q_i = F_{i,(\min(n_i-1,\ \lfloor 0.75\,n_i\rfloor))},\qquad H_i = \frac{3q_i}{30},\qquad B_i = \lceil 30 H_i \rceil
$$

**符号解释**:
- $i$ —— 任务索引(Core-50 的 50 个、Transfer-16 的 16 个)
- $F_{i,(k)}$ —— 任务 $i$ 的演示帧长序列按升序排列后的第 $k$ 项(零基索引)
- $n_i$ —— 任务 $i$ 的演示条数
- $q_i$ —— **专家 75 分位帧长**(取整位、不插值);这是全篇的「任务难度尺度」
- $H_i$ —— 物理时间预算(秒),即专家 P75 的 **3 倍**
- $B_i$ —— 最大可执行动作数,$\lceil 30 H_i\rceil$ 向上取整
- 隐含常数 **3** = 时间预算倍数;**30** = 控制频率(Hz)

**为什么重要**:它使「时间」成为**由数据派生、所有方法共享、且与被评测策略无关**的量。论文特别强调该表由策展包(含轨迹验证分区)计算,**不使用任何被评测策略的结果**。同时,`@1×` 这个副分数(在 1 倍 P75 内完成)就是用同一个 $q_i$ 定义的。

### 公式 2:有序进度(ordered progress)

$$
P_e = \frac{L_e}{K_i}
$$

**符号解释**:
- $e$ —— episode 索引
- $L_e$ —— 该 episode 中完成的**最长有效有序前缀**的阶段数(按语义操作定义;**仅仅靠近或触碰物体不算完成**)
- $K_i$ —— 任务 $i$ 的总阶段数
- $P_e \in [0,1]$ —— 该 episode 的进度分

**为什么重要**:这是**在成功率为 0 时仍能区分方法**的关键。它被用来给 Transfer-16 排序(那里所有训练型检查点成功都接近 0),也被用来诊断组合任务(「哪一步完成的、哪一步被跳过」)。论文明确:**进度永不覆盖最终成功谓词**,且 GPT-6 条件**没有分级进度测量**——因此 GPT-6 在 Transfer-16 上的 1.9% 无法与训练型方法的「有序进度」并列解读。

### 公式 3:任务定义元组

$$
\mathcal{T}_i = (\mathcal{E}_i,\ p_i(s_0),\ \mathcal{O}_i,\ \mathcal{A}_i,\ G_i,\ H_i)
$$

**符号解释**:
- $\mathcal{E}_i$ —— 任务 $i$ 的环境
- $p_i(s_0)$ —— 初始状态分布
- $\mathcal{O}_i$ —— 观测集合
- $\mathcal{A}_i$ —— 动作集合
- $G_i$ —— 成功谓词(goal predicate)
- $H_i$ —— 物理时间预算

**为什么重要**:这六个分量**全部与本体无关**。它就是 §3.1「换臂/换手/换物理后端而任务定义存活」这一架构主张的形式化依据。

### 公式 4:配对物理迁移协议与 sim-real 差值

$$
\mathcal{P}_i = (\mathcal{T}^{\mathrm{sim}}_i,\ \mathcal{T}^{\mathrm{real}}_i,\ \mathcal{C}_i),\qquad \Delta_{i,m} = S^{\mathrm{sim}}_{i,m} - S^{\mathrm{real}}_{i,m}
$$

**符号解释**:
- $\mathcal{P}_i$ —— 配对任务 $i$;$\mathcal{C}_i$ 为**对应记录**(机器人与相机配置、状态/动作坐标系、控制时序、初始化条件、成功定义)
- $m$ —— 模型;$S^{\mathrm{sim}}_{i,m}$ / $S^{\mathrm{real}}_{i,m}$ —— 模型 $m$ 在任务 $i$ 的仿真 / 真机实例上的成功率
- $\Delta_{i,m}$ —— 有符号的 sim-real 成功率差

**为什么重要**:⚠️ 这是**协议而非结果**。论文明确:本平台记录的真机 rollout 是**定性报告**(附录 F),**不构成一次带分数的物理评测**;同任务真机迁移与 Transfer-16 泛化是**两个独立的声明**。§7 把「补上配对试验预算」列为待办。

### 公式 5(可选):skill-group 回归的口径

论文 Table 8 用**任务级回归**而非直接平均来回答「skill group 的差距是不是只是数据量/时长造成的」:

- 被解释变量:任务成功率(8 个多任务检查点的均值)
- 解释变量:hand-skill group 指示变量(以 grasp–transport–release 为参照组)
- 协变量:$\ln(\text{任务训练轨迹数})$、$\ln(\text{专家 P75 时长})$
- 区间:来自 **4,000 次按组分层的任务 bootstrap** 重采样

报告口径:$R^2 = 0.62$(仅 group)→ $0.73$(加协变量);协变量系数为 $\ln(\text{轨迹数}) = -0.8\ [{-5.1}, 5.4]$(**区间含 0,即数据量解释不了差距**)与 $\ln(\text{P75}) = -11.9\ [{-16.2}, {-7.6}]$。

## 关键成果与贡献

### 证据强度评级:⭐⭐⭐(3 / 4)

**评级口径(本项目)**:⭐⭐⭐⭐ = 大样本 + 仿真与真机**双侧定量**对照 + 开放数据已核验;⭐⭐⭐ = 仿真定量 + 协议严谨 + 数据规模大,但**缺真机定量**;⭐⭐ = 仿真定量但统计或对照存在结构性缺口;⭐ = 定性或小样本。

**给 HandsOn ⭐⭐⭐ 的理由**:
- **加分项**:①45,000 次 Core-50 episode(8 检查点 39,999 次有效 + DP 5,000 次)的**大样本**;②时间预算、有效性归因、宏平均口径、有序进度、Wilson 区间、task bootstrap、跨检查点配对重采样**一整套统计纪律**;③每个任务有独立原生检查器 + 三角色分离的策展评审流程(采集者自检 → 独立评审 → 第三方仲裁,**无人评审自己的数据**);④**全任务人工可行��验证**(Core-50 50 个任务全部由策展演示完成,Transfer-16 亦经人工验证);⑤论文**主动披露**了对自己不利的信息(声明式合格豁免、call-budget 混合设置、归一化统计泄漏、单 seed、单子集抽样)。
- **扣分项**:①**真机只有定性视频,无一个成功率数字**——而论文标题里的 "Generalizable" 与 "sim-to-real" 相关表述最终只能靠仿真内部证据支撑;②**GPT-6 对照口径不可比**(观测接口、试次数、调用预算、是否 seed-paired 全部不同,论文自己声明「该比较是描述性的」);③演示规模消融**只有 1 个训练 seed、每个规模只有 1 次子集抽样**;④**归一化统计在所有规模下都来自完整训练池**,论文自陈「这不是严格的 subset-only 数据访问实验」;⑤代码/数据虽被声明为已发布,但**本报告未核验仓库内容**。

> **一句话结论**:**这是一篇「评测学 (measurement science)」论文,不是一篇「能力」论文。** 它把灵巧操控的失败结构测出来了,但没有把它解决掉。

## 局限性与未来展望

### 一、论文自述的局限(§7 Future Work,四处)

**① 触觉传感缺失(缺什么、为什么、怎么补)**
HandsOn 策略只拿视觉与本体感知,**没有触觉**。论文给出了极其具体的机理:**腕部相机是装在手上的,被握持的物体会把它们挡住——一旦抓握形成,策略必须控制的那个区域就离开了视野**。「我们报告的失败恰恰就在那里」:压在按钮上的抓握把按钮挡住的同时按下了它;丢失手柄接触的剪切发生在物体另一侧;被推过目标的物体被推它的手遮住。补触觉需要:**在仿真手与物理手上以相同方式布置 taxel**、**经验证的接触模型(而非假设的)**、以及**仍然允许视觉解法的任务**,以保证视觉策略与触觉策略在**同一谓词**上可比。

**② 缺量化的物理评估**
附录 F 的真机 rollout **是记录下来的证据,不是测量**。论文给出了一个物理成功率所需的对称性:配对的仿真/真机实例、**两侧都有可执行谓词**、**固定试验数**、**报告失败模式而非挑选成功案例**。协议已在附录 B.5 写好,**剩下的是在明确数据预算下,把它与「仿真+真机」和「纯真机」两种训练条件并行跑起来的试验预算**。

**③ 缺长时程家庭 / 生产任务**
HandsOn 评的是**单项技能**,即使是组合型 Transfer-16 任务也只串几个操作。家庭与生产工作是「几十个操作、世界状态不断变化、物体是被找到而不是被摆好、成功用吞吐与返工衡量而不是二值谓词」。论文指出这类套件**除了成功还必须测**:策略是否跟踪哪些步骤已完成、是否发现早先某步出错、能否**不重启 episode 就恢复**。这需要长时程演示、**允许恢复而非强制有序前缀的阶段模型**、以及报告进度与干预次数的评测。

**④ 缺更丰富 agent harness 下的 VLM 评测**
GPT-6 的实验只有一个 harness:`move_eef`。论文指出,当前 harness 让同一个模型同时承担选子目标、指定每个掌心位姿与**最多 40 个手指关节目标**、从图像与机器人/执行反馈中推断物体几何与接触、从被拒或无效的运动中恢复;**它没有抓取原语、没有避障规划器、没有显式物体位姿估计、没有触觉反馈**。被检视的轨迹里有**反复的运动学拒绝**和反复尝试建立/恢复抓握。论文的措辞很克制:「这提示了任务级策略与其在高维控制上的落地之间存在一个可能的鸿沟……**本实验激励了这个设计,但不建立失败率中有多少由 harness 造成,也不建立更丰富的接口能提高多少**。」

### 二、本报告在阅读中发现的额外问题

**1. 29.1% 这个数字对「通用操控」意味着什么?——它几乎什么都不意味着。**
29.1% 是**任务宏平均**,而宏平均掩盖了一个事实:成功率**沿技能轴剧烈分层**(推 51.3% → 抓-运-放 34.9% → 手指驱动 14.0% → 工具 2.9% → 精密装配 2.2%)。若按「需要通用操控能力的工序」来加权(工业关心的恰恰是精密装配、工具使用、双手交接),加权成功率会落到**远低于 29.1%**。更麻烦的是:**9 个均值超过 40% 的任务全部是「推 / 铰接 / 抓-运-放」**,而这些恰恰是**最不需要灵巧手**的任务——平行夹爪或吸盘在很多情况下也能做。**换句话说:这个基准当前测出来的「29.1%」里,相当一部分是灵巧操作最不独特的部分。**

**2. 成功是否集中在目录的一小部分?——是,但论文给了一个比直觉更好的答案。**
GPT-6 的成功极度集中(66 个任务只有 12 个有成功)。但对**训练型检查点**,论文给出了一个更严谨的读数:**41 个定目标任务上,至少一个检查点解出的场景占 62.4%,接近独立性假设下的 64.0%,检查点两两 κ 中位仅 0.03**——**不同检查点失败在不同的场景上,不存在「一小撮共同难场景」**。这意味着失败是**弥散的、策略相关的**,不是「任务选得太难」。⚠️ 但要注意 κ=0.03 的另一面:**合并多个检查点得到 62.4% 时,并没有一个单一策略能拿到 62.4%**。论文的 oracle 实验只给出 +3.8 点(29.1 → 32.9),说明**逐任务最优不等于「组合起来就能解」**——**这是「oracle 选择红利」与「真实可部署覆盖率」之间的鸿沟**,论文没有讨论,但对产业选型极其关键。

**3. Transfer-16 与 Core-50 的难度不可直接比较。**
论文三处明确分列(§3.1、§5.2.3 末、附录 C.5):「Core-50 分数衡量的是**有演示支撑的任务上的执行**,Transfer-16 测的是**留出任务**」。更微妙的是**预算口径也不同**:Core-50 的预算来自任务自身的演示 P75,而 Transfer-16 的 13 个任务用**「支撑原子任务 P75 之和 × 3」的时长代理**——论文自己说这是「**时长代理,不是组合轨迹的实测 P75**」。所以 **1.9% 与 5.2% 之间的差距,既包含泛化差距,也包含预算口径差距**,不能当成纯泛化度量。⚠️ 更进一步:**Transfer-16 成功被记在只有 3 个任务的 16 次试验上**——3/160。**这个样本量下的 1.9%,其区间是 [0.0, 3.8],上界是下界的无穷倍。**

**4. GPT-6 对比口径的可比性范围。**
论文自己已经把边界划得很清楚(§5.2.3 + 附录 C.4),但这些边界**加在一起等于「这个对照是描述性的」**:
- 试次数不同(10 vs 100)→ 逐任务分辨率只有 10 个百分点,「观察到的 0/10 不蕴含真实成功概率为 0」(附录 C.5 原话);
- 输入不同(GPT-6 拿的是实测机器人状态 + 静态任务卡;训练型策略拿的是各自的观测栈);
- 调用预算不同且**混批**(最终 100 次调用上限,但保留的早期运行有的用完整文本反馈、有的超过 100 次)→ **不是一次受控消融**;
- **不 seed-paired**;
- **无分级进度测量** → 在 Transfer-16 上无法与训练型方法的有序进度并列;
- 且 GPT-6 **不接收物体位姿、隐藏奖励与实时检查器状态**,而任务卡里对三个基础 pick-and-place 任务有**目标澄清文本**、对 Lift Carton 有**声明的评分例外**——**这些额外文本本身就构成信息优势**。

> **本报告的判断**:**「5.2% vs 29.1%」这个对比在论文里的正确读法是「在当前这个极简接口下,提示式 VLM 的直接灵巧操控还远不及专用策略」,而不是「通用模型比专用模型差 6 倍」。** 论文没有做匹配消融,任何把它当成架构能力结论的引用都是越界。

**5. 试验次数与置信区间:统计效力在两个层级上都不够。**
- **GPT-6**:每任务 10 次、每任务 20,000 次 bootstrap 重采样的**条件**区间,**排除**任务选择、provider/模型版本、协议设置三类不确定性。**核心 50 任务的 5.2% 的 CI 是 [3.6, 6.8]——宽度 3.2 个百分点,而方法间差距动辄 5–10 点。**
- **训练型检查点**:100 次/任务是够的(宏分数半宽 0.9 点),但**逐任务只有 6 个任务的信噪比 < 1**;**「OpenWAM 29.1%」是一个跨 50 任务、每任务 100 次的聚合,不是任何单任务的结论**。
- **演示规模消融**:**每个规模只有 1 个 seed、1 次子集抽样**;Wilson 区间是「给定该 checkpoint 的 rollout 级二项不确定性」。从 200 条到全量的 +18/+26 点**无法排除子集抽样运气**。
- ⚠️ **归一化泄漏**:所有规模的归一化统计都来自完整训练池,小数据 run 因此「看得见」更大池的摘要统计。论文自陈「这不是严格的 subset-only 数据访问实验」——**这条自陈应该被更多引用**。

**6. 是否依赖特权状态 (privileged state)?**
从文本看:**任务定义层面的特权是有的**(原生检查器状态、物体位姿、阶段计数),但**策略侧应当没有**——论文反复强调「checkpoint 自有的表征、预处理与归一化」被保留,「完整精度仿真状态、动作、响应与执行诊断**保留用于核验**」,GPT-6 侧的「物体位姿、隐藏奖励、实时任务检查器状态**不提供给模型**」。⚠️ 但有两条**明确的例外**,值得任何复现者盯住:
- **GPT-6 接收「实测机器人状态」(measured palm poses and finger joints)**。这不是纯像素输入。它同时接收**静态任务卡**,其中包含三个基础 pick-and-place 任务的**目标澄清**和 **Lift Carton 的声明式评分例外**。
- **两个任务级豁免被显式声明**:Open Latched Door 的**冻结指令与其原生源存在已知不匹配**;**Lift Carton 放弃了 12 N 力阈值**。论文很诚实地把这两条标为「声明的合格条件」,但**任何读者在引用「Lift Carton 有 4 次成功」时都必须知道这不是一个 12 N 力限下的成功**。

**7. 真机 rollout 只是定性演示——这与「Generalizable」这个标题词存在张力。**
论文对附录 F 的自陈非常克制:视频覆盖**少量 episode、一个物理平台**、**没有配对的「仿真+真机」或「纯真机」训练条件(在匹配数据预算下)**、**没有报告任何成功率**;并明确「**我们不因此用它量化物理迁移**」,把预算受控的对比列为未来工作。
> **本报告的判断**:**这篇论文的标题里同时有 "Generalizable" 和 "Large-Scale Simulation Benchmark",但 "Generalizable" 在本文的证据下只覆盖「跨任务/跨资产/跨本体的仿真内泛化」,不覆盖「跨到物理世界」。** 跨本体这一维度尤其要注意:§4.6 明确**所有实验只用一套配置**(ROKAE AR5-08 + 第一代 Wuji Hand + PhysX),**其余被支持的臂/手/后端没有贡献任何 episode**。所以本文**没有**提供「同一策略在多个本体上跑」的证据,**「跨本体」目前是架构能力声明,不是实验结论**。

**8. 「演示规模解释不了差距」这个结论的射程。**
§5.3.1 的单任务曲线(Task 24: 7 → 83%;Task 43: 1 → 44%)看起来像是「数据能解决一切」,但它有两个关键限定:
- 归一化统计用全量池(泄漏);
- **这两条曲线都在「抓-运-放」与「单手工具」这一类技能上**,而 Table 8 显示**精密装配组的轨迹数中位(413)已经高于抓-运-放(392)**,却低 30+ 点。
> **所以正确表述是:「对抓-运-放和单手工具这类任务,更多演示确实能换到更高成功率;但对精密装配与工具作用于他物,**轨迹数已经不是约束条件**——约束条件是技能本身(接触角色区分、双手时序、状态维持)。** 这也是本文对社区最有价值的一句潜台词。

### 三、未来方向

**论文提出的(§7 + §6)**:
1. **触觉**:仿真与物理手同位 taxel + 经验证的接触模型 + 保留视觉可解性的任务设计,使视觉/触觉策略在同一谓词上可比;
2. **量化物理评估**:执行附录 B.5 的配对协议,并在明确数据预算下对比「仿真+真机」与「纯真机」;
3. **长时程家庭与生产任务**:允许恢复的阶段模型 + 报告进度与干预次数的评测;
4. **更丰富 harness 下的 VLM 评测**:固定模型比较 harness、固定 harness 比较模型;匹配任务、reset、物理时间与查询预算;披露低层技能的来源;同时测成功、子目标完成、恢复与推理成本。
5. **§6 的建模方向**:显式建模**接触角色 (contact role)**、**手间依赖 (inter-hand dependency)**、**任务进度 (task progress)**。

**本报告推断的(论文未提但由其数据直接支持)**:
- **「接触角色分类」应当成为独立的方法学目标**。表 2 显示三类失败(接触建立的三种子形态)本质上都是「同一个接触既被用来稳定、又被动用了功能」。论文已经把这三种形态分得很干净(功能在持握接触之下 / 功能是独立手指 / 持握与驱动共用手指)——**这可以直接变成一个可用于训练或评估的标签体系**,而论文自己没有把它提出为方法。
- **「维持已达目标」需要一个独立的状态机,而不只是更好的策略**。Set Dual Knobs(5/800)、Cover Pitcher(47/86 保持插入)、Pass Block(175/179 掉落)这三个数字,量级上更像**协议缺陷**(缺少「保持」语义)而不只是策略缺陷。论文其实已经指出「success 谓词包含释放、稳定性或停留要求」,但**它没有把这些保持要求做成可被策略显式查询/预测的接口**。
- **应当为「组合任务」引入显式的步骤完成标记**。§5.3.3 的第四类失败(「没有东西标记一个已完成的步骤,完成度只能从场景推断」)是一个**接口缺陷**,不只是策略缺陷。一个带阶段标签的观测或动作接口,可能比更大的策略更有效——这是本文数据指向的、但论文没有展开的方向。
- **执行器 / 规划器的失败应当与策略的失败分开记账**。论文自己的 30 Hz 原生执行器、100 次调用预算、300 动作调度上限,都会把「模型决策错」与「接口能力不够」混在一起。表 2 的「工具被绕过」(81% / 44% / 28%)尤其可疑:那更像是**策略没学会用工具**,但也可能与执行器的路径规划无障碍物模型有关(附录 C.2 明说规划器无障碍物模型)。

## 应用与行业映射

### 1. 应用方向:谁会拿这个基准来选型/验收

**先给结论:这个基准当前最适合的角色不是「能力验收工具」,而是「供应商/客户对齐语言」和「研发诊断工具」。** 理由是 29.1% 的绝对水平与 2.2%–2.9% 的精密装配/工具类成绩离产线验收标准(通常要求 ≥ 99% 单次成功率、且通常带人工干预兜底)太远。

**「谁会拿它来验收」的具体清单**(本报告的推断):
- **灵巧手厂商 → 客户采购谈判**:用「你们的 Wuji/Sharpa 在 Core-50 的 Precision fit 组只有 X%」作为对比参数。⚠️ **但注意**:基准只跑过 ROKAE + 第一代 Wuji + PhysX 这一套,**厂商要引用本基准谈自家手的表现,需要自己实现 arm/hand 替换并接受「跨配置数字不可比」的代价**。
- **VLA / WAM 基础模型团队** → **模型选型与迭代看板**。Table 5 的「WAM 慢但更全、VLA 快但更少」的 @1× vs @3× 双分数,以及 skill-group 分层,是模型迭代最直接的目标函数。
- **云厂商 / 仿真平台方** → **Isaac Sim 的差异化卖点**(18,000 条现成演示 + 66 个人工验证任务 + 严格协议)。
- **研究机构** → **失败归因工具**。表 2 的四类失败可以直接变成新方法的目标函数。

**成本量级对比(本报告的判断,非论文数据)**:
- **数据成本**:HandsOn 的 18,000 条是**纯仿真人工遥操作**,在 Isaac Sim 内完成(数据本体即仿真,没有真机磨损)。成本主要是**人力**(≥10 人、>1,050 session)+ **重渲染算力**。⚠️ **论文未披露这两个数字**。
- **替代路径的成本**:若目标是「有 benchmark 语义的灵巧演示」,真机遥操作 56 小时在商用 20 自由度灵巧手上是**每周级工位占用**(每条 20 DoF 轨迹 + 重置),量级上远高于仿真采集。**这正是 HandsOn 最硬的产业价值:它把「基准级演示数据」的边际成本从「真机工位周」压到「仿真 GPU 时」——但代价是 sim2real 差距由基准本身承担,而本文没有量化这个差距(真机只有定性视频)。**
- **性能对比**:不同基准的绝对成功率**不可直接比**(任务集、成功谓词、reset 分布、预算全不同)。HandsOn 内部最有价值的对比是**@1× vs @3× 双分数**,它暴露了「WAM 慢而全、VLA 快而少」这一被单分数掩盖的取舍。

### 4. 量产壁垒

**按环节拆解(标注本文提供的证据强度)**:

| 环节 | 壁垒 | 本文证据 |
|---|---|---|
| **① 本体硬件成本** | **本文不构成瓶颈,但也不消除瓶颈**。真机侧 ROKAE AR5-08(7 DoF / 5 kg / 683 mm)+ 第一代 Wuji Hand(20 主动关节)是**已有商品件**;论文给出厂商标称重复精度 ±0.1 mm、底层 1 kHz 位置控制。⚠️ **论文未给价格** | ✓ 中等证据(有规格,无成本) |
| **② 训练数据** | **这是本文的最大贡献,也是最大的残余风险**。18,000 条带 checker 对齐的演示被论文声称已发布 → 边际数据成本从「真机工位周」降到「下载 + 微调」。⚠️ **但 sim2real 差距未被量化**(真机只有定性视频、无成功率) | ✓ 数据侧强(规模与规约) / ⚠️ **迁移侧无定量证据** |
| **③ 算力** | ⚠️ **论文完全未披露 GPU 型号与墙钟时长**。仅能从更新步数推断量级:八个多任务检查点合计约 **753,000 次更新**,DP 侧另 **50 × 30,000**。单任务消融是 **20,000 次更新 / batch 32**,这是可复现的最小单位 | ⚠️ **弱证据**(无成本数字) |
| **④ 可靠性** | **这才是真正的卡点**。表 2 的四类失败全部指向「**状态维持**」:同时保持两个旋钮(5/800)、盖子插入后保持(47/86)、交接时不掉落(175/179)、盖子叠好(30/164)、组合任务步骤顺序(311/399 先按快门)。**在产线上,一个「通常能成但偶尔掉」的工序等于不可用** | ✓ **强证据**(多个任务上的大样本计数) |
| **⑤ 感知与接触** | **触觉缺失被论文明确列为首要未来工作**。机理写得很清楚:腕部相机装在手上,**抓握形成时必须控制的那块区域正好离开视野**。而工业精密装配恰恰依赖触觉 | ✓ **强证据**(论文自陈 + 失败定位吻合) |
| **⑥ 安全认证** | ⚠️ **本文完全未涉及**。没有力/速度上限、碰撞检测、冗余急停、ISO 10218 / ISO 13485 / IEC 60601 等合规维度。**论文的 30 Hz 原生执行器 + 52 维动作接口不是可认证的产品接口** | ✗ **无证据** |
| **⑦ 「最后一公里」:真机验证** | ⚠️ **这是最尴尬的一环**。论文把配对物理协议写好了(附录 B.5)却**没有执行**:没有配对的仿真+真机 vs 纯真机训练对照、**没有一个真机成功率数字**。产业选型最需要的恰恰是这个数字 | ✗ **无证据**(论文自陈) |

> **本报告的总结判断**:**壁垒不在「有没有基准」,而在「基准到产线之间的那 12 米」。** HandsOn 把「灵巧操作能不能学会」这个问题的**研发成本**降了一个数量级,但**没有降低「做出来能不能用」的验证成本**——恰恰相反,它**提高了对验证精度的要求**:一旦你有了 18,000 条演示和 50 个严格 checker,任何只报告「仿真里成功率 30%」的产品宣称就变得**不可接受**,因为受众现在可以要求你给出「在带保持条件、时序条件、接触角色条件的任务上」的数字。

### 5. 时间窗估计

**1 年内(2027)——「基准成为行业通用词汇,而不是验收标准」**

- **可核查依据**:
  1. 论文已把协议写成**可被他人使用**的形式(冻结时长表、原生 checker 任务卡、诊断口径、有序进度、Bootstrap 口径),任何团队都能据此做自己的实现;
  2. arXiv abs 页已挂 **ancillary files**(`README.txt`、`scaling_results_20260926.json`),说明作者在做**可复现性配套**,这是社区接受的前置条件;
  3. 论文的对比表已经覆盖 **5 个 VLA + 3 个 WAM + DP + GPT-6**,其中 π0.5、DM0.5、HuggingFace 系模型都在活跃迭代 —— **基准会随模型版本自动更新**,而**基座模型团队有强动机去刷它**(如同刷 ManiSkill / LIBERO / RoboArena);
  4. 但 29.1% 的绝对水平、2.2%–2.9% 的精密装配水平,**距产线验收标准差 1–2 个数量级**。
- **判断**:到 2027 年底,HandsOn **大概率会成为灵巧操控领域的「主口径引用」之一**(类似 LIBERO / ManiSkill 在操作领域的地位),出现在 VLA/WAM 论文的对比表里;但**不会有产线用它做验收**。**「按 HandsOn 分类报告成功率」会成为论文评审与内部技术评审的默契动作。**
- **触发信号(可核查)**:是否出现**第二个独立团队**在 HandsOn 上报告结果 —— 这是基准从「作者自留地」变成「公共基准」的唯一硬指标。

**3 年内(2028)——「基准 + 触觉 + 物理配对评测」成形,开始影响选型」**

- **可核查依据**:
  1. 论文 §7 列出的四条未来工作(触觉、量化物理、长时程、丰富 harness)**都是**「有明确工程路径的」类型 —— 触觉需要仿真/物理同位 taxel(这是可做的工程,不是研究难题);配对物理协议已经写好(附录 B.5),**缺的只是试验预算**;
  2. WAM 家族的强势(OpenWAM 29.1%、FastWAM 26.4% vs π0.5 24.9%)说明**「预测未来观测」这条路线在灵巧操作上确有增益**,而它在 2026-2028 仍在早期;
  3. 触觉一旦进入基准,「手指驱动 14.0%」「工具 2.9%」「精密装配 2.2%」这三组极低分**几乎必然上升** —— 因为这些失败全部是「接触角色分不清」,而触觉直接观测接触事件;
  4. 产业侧:按本项目行业格局文档的口径,灵巧手正在从「样机」走向「批量交付」,**采购方需要一个能跨供应商比较的验收语言** —— 这正是基准的供给侧。
- **判断**:到 2028 年,HandsOn(或它的继承者)**很可能成为灵巧手供应商的选型基准**,尤其是**精密装配与工具使用**这两组;并大概率**出现第一个带真机成功率的 HandsOn 配对结果**。
- **触发信号**:①附录 B.5 的配对协议被实际执行并公开真机成功率;②触觉版任务集公开;③出现**第二篇以 HandsOn 为主战场的方法论文**(而非把它当对比表的一行)。

**5 年内(2030)——「基准的规格被吸收进采购合同,或者被一个更大的平台吞掉」**

- **可核查依据(两种互斥路径)**:
  - **路径 A(基准独立存续)**:HandsOn 保持「协议权威」的地位,成为灵巧操控领域的**事实标准测量仪**,并随产业需求长出**分级**:桌面对桌面 → 产线节拍(带吞吐与返工率)→ 长时程家庭。§7 已经指出这需要「允许恢复的阶段模型」和「报告进度与干预次数」—— 这是**协议层面的演进**,不是重做基准。
  - **路径 B(被平台吞掉)**:⚠️ **风险更高**。NVIDIA 已经同时握有 Isaac Sim、PhysX、Isaac Lab、GR00T 和本文的数据采集环境。若 NVIDIA 把等价资产做成 **Isaac Lab 官方 benchmark**,HandsOn 的**协议权威**会保留,但**数据入口**会迁到 Isaac 生态。论文支持 Newton 后端这件事,说明作者**主动在做去锁定**,这既是优点也意味着**它不打算成为某个平台的私产**。
  - **另一条不可忽视的路径**:一个**更大规模的综述型基准**(如覆盖人形 + 灵巧 + 移动的全栈基准)可能把 HandsOn 吞成一个子集 —— BiGym 2.0 那条「人形家务」线与本文的「桌面灵巧」线,合流是自然的方向。
- **判断**:到 2030 年,「**用某个公开基准的分组成功率来描述灵巧手能力**」应当已是行业常规;但**具体是 HandsOn 这个名字还是别的名字,是开放的**。**更重要的是,本报告判断:即使 HandsOn 被取代,它的「四类失败分解」这一分析框架也会留下来 —— 因为它是第一个把「灵巧失败」拆到「接触角色 / 手间依赖 / 状态维持 / 步骤时序」这四个可工程化维度的公开工作。**

### 与论文 Table 1 的自比(交叉核对)

论文自己的 Table 1 把 HandsOn 与 DexJoCo / DexVerse / Bench2Dex / DMG / SPD 并列。要点是:**HandsOn 的差异化不在任务数(50+16 不如 DexVerse 的 100),而在「测试专用任务」这一列只有它填了数(16)**,以及「额外诊断」列的粒度(转移点 / 保持率 / 接触)。这与本报告的判断一致:**HandsOn 的贡献是「协议深度」而非「广度」。**

### 三条可直接对比的产业结论(跨报告)

1. **数据成本的两个极端已被本项目覆盖**:Dex-One2Many = **1 条演示**;HandsOn = **18,000 条演示**。二者之间是同一空间里的不同工程选择。HandsOn 自身的规模消融给出关键信息:**对抓-运-放,10 → 438 条能换到 7% → 83%**;而**对精密装配,轨迹数中位(413)已经高于抓-运-放(392)却低 30+ 点**。→ **「先要多少数据」这个问题,在灵巧操作的答案不是常数,而是技能类型的函数。**
2. **「成功率」在跨基准之间不可比,在同一基准内也要看两个分数**:HandsOn 的 @1× vs @3× 让 28 个配对里的 12 对改变顺序。**任何只报一个数字的灵巧操控对比,都可能因为时间预算口径而翻转结论。**
3. **开源程度与证据强度不是同一件事**:BiGym 2.0 完全开源(本项目已收录)、HandsOn 声称已发布但本报告未核验、Dex-One2Many 与 BlindBaoding 未开源。**一个未开源的基准,它的数字对社区是「不可复核的声明」** —— 这直接影响它在产业选型中的权重。

## 一句话总结

**HandsOn 用 18,000 条人工仿真演示和 66 个人工验证任务,证明了「灵巧操控的失败是可被归因到具体接触与具体时刻的」——它给出的最好成绩是 29.1%(OpenWAM,Core-50),GPT-6 在 660 次零样本试验中只拿到 5.2% / 1.9%,而最硬的三个数字是:精密装配 2.2%、工具作用于他物 2.9%、双手同时保持旋钮 5/800。** 这篇论文测出了一整套产业界此前只能靠直觉争论的差距,并把它拆成了可工程化的四个维度(接触角色 / 手间依赖 / 状态维持 / 步骤时序)——但它**没有**提供任何真机定量证据,**跨本体**也只停留在架构声明层面。因此:**它是一把极好的尺子,不是一个已经够用的答案。**
