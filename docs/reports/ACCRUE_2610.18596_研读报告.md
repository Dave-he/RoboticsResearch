## 核心问题

这篇论文问的是一个**部署侧的问题,而不是一个算法侧的问题**:

1. **现有 RL 后训练把「部署」当成了「一次性事件」。**
   绝大多数 RFM(robot foundation model)后训练工作把 post-training 当作**针对单一目标任务的一次性流程**。但真实机器人部署是:**机器人必须在其整个服役期内不断学习新任务,而且事先拿不到未来的任务列表**。论文用**机器人装配**举例:新产品、新零件变体不断出现,机器人要**适配接触行为,同时保留此前已学会的装配技能**。**每次任务都重启 RL,就等于反复支付完整的交互成本,并且浪费掉前一阶段积累的 RL 知识。**

2. **根因:两条已有路线各自只解决一半。**
   - **持续 VLA 的 on-policy RL 方法**(Simple Recipe 等):能缓解遗忘,但**需要当前策略的全新 rollout**,前向迁移有限,交互成本高。
   - **轻量 off-policy 后训练方法**(RL Token、EXPO-FT):在冻结 RFM 上挂轻量 actor/critic,**单任务样本效率高**,但**完全没考虑 learner 能否跨任务延续**。
   把 off-policy 直接跨任务延展,会遇到论文明确列出的三个实践难题:
   - **(a) 记忆成本**:保留全部交互历史随任务数增长而不可承受 → 需要小 replay memory;
   - **(b) critic 在旧任务上不可靠**:只有少量旧任务覆盖时,继承来的 critic 在早期任务上的估计不可靠 → **用这些估计去驱动 actor 在旧样本上的更新,会侵蚀已学行为**;
   - **(c) 基座在变**:更新 base RFM 会改变其内部表征与动作提议,**从而改变继承网络所消费的输入分布**。

3. **新的视角:非对称更新。**
   ACCRUE 的核心主张是 **Actor–Critic Carryover for continual off-policy Reinforcement learning Using retained Experience**:
   - **critic 只在当前任务转移上学**(接受它对旧任务不可靠);
   - **actor 的旧任务行为用「向上一阶段 actor 的缓存输出蒸馏」来保住**,**完全不让 critic 参与旧行为的维持**。
   论文的措辞很准确:「**这种非对称更新保留了 actor–critic 继承的好处,又不依赖 critic 来保存旧任务行为。**」

## 方法论与核心思路

### 问题设定(§3.2)—— 这部分定义得比多数论文严谨,值得单独讲

- 机器人顺序习得 **$K$ 个任务,每阶段一个任务** $T_k$。各任务**共享状态空间、动作空间与折扣 $\gamma$**,但**可以有不同的转移函数、奖励函数、初始状态分布与 horizon**。
- 任务身份**已知**(task-incremental continual learning 设定)。
- 第 $k$ 阶段来一份小的专家演示集 $\mathcal{D}_k$(论文实验中 **1–50 条轨迹**)。基座在**截至该阶段为止累积的** $\mathcal{D}_{1:k}$ 上微调,得到 $\pi^k_{base}$,**然后在该阶段的整个 RL 期间保持固定**。
- 目标函数:**最大化所有已见任务上的平均回报** $\max_\pi J(\pi) = \sum_k \frac{1}{L_\tau}\mathbb{E}_{\tau\sim(\pi^k, T^i_k)}[\sum_t \gamma^i r^i_t]$。

**论文明确声明了一个重要的协议区别**:与「先把基座在全任务集上微调完、再开始持续 RL」的协议不同,本文**既不假设能访问未来演示,也不假设基座在整个序列中固定**。

### 整体架构

```
   ┌───────────────────────── 每阶段重复 ─────────────────────────┐
   │                                                                 │
   │   [1] 基座更新:  π_base^k ← FineTune(π_base^(k-1), D_1:k)      │
   │                    (冻结: off-the-shelf 视觉编码器 E 跨阶段不动) │
   │                          ↓ 参考动作 chunk ã_t                 │
   │   视觉观测 I_t ──► 冻结视觉编码器 E ──► 视觉特征 ──┐          │
   │                                                    ├─► s_t   │
   │   本体感知 q_t ────────────────────────────────────┘          │
   │                                                                 │
   │   [2] 承接:  (θ_k, ψ_k) ← (θ_(k-1), ψ_(k-1))   ← handoff      │
   │                          &  ℬ_<k (旧任务最后 N 条 episode)    │
   │                                                                 │
   │   [3] 缓存教师目标:  â_j^(k-1) = π̄_θ(k-1)(s_j, ã_j)  一次性    │
   │                                                                 │

   └─────────────────────────────────────────────────────────────────┘

                            ▼  返回 ℬ_k 的最后 N 条 episode → 下一阶段 handoff
```

### 关键设计 1:固定外部视觉编码器(解「基座在变」)

这是论文解决难题 **(c)** 的办法,而且做得很干净:

> 「要让 actor 与 critic 跨阶段承接,它们的视觉输入必须在基座被更新时保持一致的表征。因此我们使用一个**独立于基座、跨阶段冻结**的现成视觉编码器 $\mathcal{E}$。」

具体做法:**replay buffer 存的是 $s_t = (\mathcal{E}(I_t), q_t)$,而不是 projector 的输出。** projector 本身是可训练的(属于 $\theta$ / $\psi$),但**编码特征是冻结的** —— 所以第 $i$ 阶段存下的转移,在第 $k$ 阶段仍然是同一表征。

论文自己诚实标注了这一对照的局限(Table 4 的 `DINOv3 → GR00T VLM` 行):**「虽然这个对照同时更换了编码器本身,因此并没有隔离出表征漂移」** —— 但它仍然支持固定视觉接口的实际优势。

### 关键设计 2:参考动作条件(而不是重建技能)

actor 与 critic **都不直接编码语言指令**。任务身份决定了给基座的指令 $\ell_k$,基座产出参考 chunk $\tilde a_t$;actor 与 critic **条件在这个参考上**:

$$a_t \sim \pi_\theta(s_t, \tilde a_t),\qquad Q_\psi(s_t, a_t, \tilde a_t)$$

论文的论证很干净:**「因为基座已经编码了任务语义并提供了任务级的动作提议,轻量 actor 学的是一个条件于 $\tilde a$ 的局部修正,而不是重建完整技能。」** 这带来一个直接的持续学习收益:**需要保持稳定的共享 actor 行为被压缩到「RL 获得的修正量」这一小块。**

两个配套设计:
- **参考动作丢弃(reference action dropout)**:训练时以随机比例 $p$ 把 $\tilde a$ 置零(actor 与 critic 都置零),**防止 actor 只是照抄参考**。
- **critic 也要条件于 $\tilde a$**(与 RL Token 不同,后者只条件 actor)。论文理由:**动作价值是任务依赖的,参考提供了任务上下文。**

### 关键设计 3:非对称更新(解「critic 在旧任务上不可靠」)

这是全文的方法论核心,论文的逻辑链完整:

1. **critic 的 TD 更新只作用于 $\mathcal{B}_k$**。理由原话:「虽然我们也可以用 $\mathcal{B}_{<k}$ 做 critic 学习,但每个旧任务只保留 $N$ 条 episode,可能不足以可靠地保持它对旧任务的价值估计。」
2. **actor 的 RL 目标(Eq. 1)也只作用于 $\mathcal{B}_k$**。理由:「对这些 $\mathcal{B}_{<k}$ 样本施加 actor RL 目标,可能把不准确的 critic 估计转化为已学行为中的漂移。」
3. **旧行为靠蒸馏保住**:用**上一阶段 actor 的冻结副本**在保留样本上产生确定性输出 $\hat a_j^{(k-1)} = \bar\pi_{\theta_{k-1}}(s_j, \tilde a_j)$,**这些目标在整个第 $k$ 阶段保持固定,缓存后教师副本即丢弃**。
4. **关键的对齐细节**:**行为目标每阶段从上阶段 actor 刷新,但参考 chunk $\tilde a_j$ 保留其原始值** —— 这保证**教师与学生看到的是同一组先前观测到的输入 $(s_j, \tilde a_j)$**。若参考也刷新,蒸馏就会变成「对齐到新基座的动作」,反而可能加速遗忘。
5. **每阶段 actor 更新使用 1:1 的当前任务 : 旧任务样本比例**,分别从 $\mathcal{B}_k$ 与 $\mathcal{B}_{<k}$ 采样成独立 minibatch。

### 关键设计 4:chunk 级 TD(把信用分配路径缩短 H 倍)

$$\sum_{h=0}^{H-1}\gamma^h r_{t+h} \equiv R_t^{(H)}$$

$$Q_\psi(s_t, a_t) \approx R_t^{(H)} + \gamma^H \mathbb{E}_{a'\sim\pi_\theta(\cdot|s_{t+H})}[Q_\psi(s_{t+H}, a')]$$

论文的表述:「**相较于单动作 backup,chunk 级 backup 把名义上的信用分配路径缩短了 $H$ 倍。**」实现上,**critic 在固定支撑集上预测分类回报分布**,用**交叉熵损失**训练(论文说**在稀疏奖励下比 MSE 更稳定**),$Q_\psi$ 表示其期望值。

## 核心公式提取

以下全部取自原文编号。

**(1) 当前任务 actor 目标(带参考偏离惩罚)**

$$\mathcal{L}^{cur}_{\pi}(\theta;\mathcal{B}_k)=\mathbb{E}_{(s,\tilde a)\sim\mathcal{B}_k}\Big[-Q_\psi\big(s,a,\tilde a\big)+\beta\|a-\tilde a\|^2\Big],\qquad a\sim\pi_\theta(s,\tilde a)$$

**符号**:$\beta$ —— 偏离参考动作的惩罚系数(仿真 **0.1**,真机 **10.0**)。论文的解释:「$\beta$ 惩罚偏离参考动作,**把学习降为对基座动作分布的局部修正,而不是在 $Hd$ 维动作空间上穷举搜索。**」

**(2) chunk 级 TD 目标**

$$\hat{Q}=R_t^{(H)}+\gamma^H Q_{\psi'}(s_{t+H},a_{t+H},\tilde a_{t+H})$$

$\psi'$ 为目标 critic 参数。$a_{t+H}$ 对随机型 learner 从 actor 采样、对确定性 learner 用目标动作规则构造。

**(3) 蒸馏目标缓存**

$$\hat a_j^{k-1}=\bar\pi_{\theta_{k-1}}(s_j,\tilde a_j),\qquad j\in\mathcal{B}_{<k}$$

$\bar\pi$ 指**不含动作采样、不含探索噪声的确定性评估输出**。

**(4) 旧任务蒸馏损失**

$$\mathcal{L}^{prior}_{\pi}\big(\theta;\mathcal{B}_{<k}\big)=\mathbb{E}_{j\sim\mathcal{B}_{<k}}\Big[\big\|\bar\pi_\theta(s_j,\tilde a_j)-\hat a_j^{k-1}\big\|^2\Big]$$

**(5) 总 actor 目标**

$$\mathcal{L}^{prior}_{\pi}\big(\theta;\mathcal{B}_k\big)=\mathcal{L}^{cur}_{\pi}\big(\theta;\mathcal{B}_k\big)+\lambda\,\mathcal{L}^{prior}_{\pi}\big(\theta;\mathcal{B}_{<k}\big)$$

⚠️ **注:原文 Eq.(5) 左侧印刷为 $\mathcal{L}^{prior}_\pi(\theta;\mathcal{B}_k)$(标 prior 但缓冲写 $\mathcal{B}_k$),这看起来是排版笔误** —— 右侧第一项明确用 $\mathcal{B}_k$,第二项明确用 $\mathcal{B}_{<k}$ 与权重 $\lambda$,故左侧应为总损失符号。**本报告按语义理解引用,已如实标注。**

**指标定义(§3.2 / §5.1,原文给出)**

设 $c_{i,j,e}$ 为第 $i$ 阶段训练 $e$ 步后任务 $j$ 的成功率,$c_{i,i}=\max_e c_{i,i,e}$,$c_{i,j}=c_{i,j,e^*_i}$(取**最早**的达到最大值的 checkpoint):

$$FWT_k=\frac{1}{|\mathcal{E}|}\sum_{e\in\mathcal{E}}c_{k,k,e},\qquad NBT_k=\frac{1}{K-k}\sum_{m=k+1}^{K}\big(c_{k,k}-c_{m,k}\big)$$

$$AUC_k=\frac{1}{K-k+1}\Big[FWT_k+\sum_{m=k+1}^{K}c_{m,k}\Big],\qquad ACC_{final}=\frac{1}{K}\sum_k c_{K,k},\qquad F_{final}=\frac{1}{K-1}\sum_{k<K}\big(c_{k,k}-c_{K,k}\big)$$

**FWT / NBT 在 $k\in[K]$ 上平均,NBT 在 $k\in[K-1]$ 上平均。** 论文对 NBT 与 $F_{final}$ 的区分说得很清楚:**「与 NBT 不同,$F_{final}$ 忽略瞬时性能下降,只度量序列末端的遗忘。」** 这两个都描述「端到端部署表现」。

> **本报告的方法论提醒**:AUC 的定义把「新任务的学习曲线」(FWT,受评测网格 $\mathcal{E}$ 影响)与「旧任务的保持」直接相加,**两者量纲相同但语义不同**;而 $F_{final}$ **只取序列末端**,对「中途短暂下降后恢复」的情况不敏感。**读者应同时看 NBT、FWT、ACC_final 三个原始指标,而不是只看 AUC。**

1. **遗忘几乎被消除。** 在严格可比的共享 actor–critic 组里,ACCRUE 的 NBT 为 **0.065 / 0.047**,而最强基线 ER 是 **0.518 / 0.167** —— **FORGE 上把负向后迁移降了约 87.5%,AutoMate 上降了约 71.9%**(本报告按表内数值计算;论文摘要表述为「相对最强 off-policy 持续基线降低负向后迁移最多 70.0%」)。
2. **最终部署精度大幅提升**:ACC_final **0.917 / 0.863**,而 $\pi_{base}$ 只有 **0.687 / 0.757** —— **即相对未做 RL 的基座,末端部署性能提升 23.0 / 10.6 个百分点。**
3. **同时击败了两个不同范式的对手**:不仅打败所有共享 actor–critic 方法,也**在同样 VLA backbone、同样每阶段交互预算下打败了外部参考 Simple Recipe**(NBT 0.065 vs 0.038 但 AUC 0.869 vs 0.583、FWT 0.823 vs 0.586 —— **注意 Simple Recipe 的 NBT 其实更低,论文的声明是「AUC 与 FWT 更低」,这是诚实但需要注意的口径**)。
4. **逼近「特权」参考 Isolated**:Isolated 为每个任务保留一份独立 checkpoint(避免共享参数干扰,代价是**每个任务存一个 learner**),ACCRUE 在 FORGE 上 ACC_final 0.917 vs 0.919、AutoMate 上 0.863 vs 0.879 —— **用单一共享 actor–critic 逼近了「每任务一份模型」的存储方案。**

> ⚠️ **本报告需要指出的一处口径问题**:Simple Recipe 的 NBT(0.038 / 0.016)**低于** ACCRUE(0.065 / 0.047)。摘要里「reduces negative backward transfer by up to 70.0% compared with the strongest off-policy continual baseline」这句话**限定在「off-policy 持续基线」范围内,是成立的**;但若读者把它读成「比所有基线遗忘都低」则不成立。**论文在正文的措辞是精确的,摘要的口径边界值得读者自行核对。**

### 2. 真机结果(DROID,§5.3)—— 全文最有产业价值的数字

**设定**:$\pi_0.5$ + LoRA 微调(5 或 10 条 SpaceMouse 演示)+ **FastTD3** + $H=10$ + 每阶段保留 20 条 episode,异步采集,**95%(19/20)即停**。

### 3. 消融(Table 4,FORGE S1 序列,固定任务序列/阶段预算/所有共享超参)

| 配置 | NBT ↓ | FWT ↑ | AUC ↑ | ACC_final ↑ | F_final ↓ |
|---|---|---|---|---|---|
| **ACCRUE** | **0.028** | **0.854** | **0.906** | **0.961** | **0.037** |
| DINOv3 → GR00T VLM(换编码器) | 0.071 | 0.814 | 0.846 | 0.883 | 0.113 |
| $\pi_\theta(s,\tilde a)\to\pi_\theta(s)$(去掉参考条件) | 0.035 | 0.807 | 0.869 | 0.936 | 0.050 |
| $\beta = 0.0$(去掉参考偏离惩罚) | 0.029 | **0.763** | 0.821 | 0.942 | 0.037 |
| Reset Critic(每阶段重置 critic) | 0.042 | 0.841 | 0.890 | 0.942 | 0.054 |
| Update Critic w/ $\mathcal{B}_{<k}\cup\mathcal{B}_k$ | 0.037 | 0.842 | 0.888 | 0.925 | 0.067 |

**每条消融对应论文的一个明确论断:**

- **换编码器 → NBT 0.028→0.071、F_final 0.037→0.113(3 倍)**。论文诚实标注该对照「同时更换了编码器本身,未隔离表征漂移」。
- **去掉参考条件 → FWT 0.854→0.807、NBT 0.028→0.035**。论文:「去掉参考动作输入同样降低了保持与迁移,**证明参考动作提供了超出视觉状态本身的有用条件信息**。」
- **$\beta=0$ → FWT 0.854→0.763(掉 9 个百分点),但 NBT 几乎不变(0.028→0.029)**。论文的关键区分:「去掉参考偏离惩罚**对向后保持影响很小,但显著削弱前向迁移与任务学习**。显式地把 actor 偏向参考动作,是支持高效局部修正、而非保持旧行为。」**这条消融把「保持」和「学习」两个作用干净地分开了 —— 是本文实验设计最漂亮的一处。**
- **重置 critic → NBT 0.042、AUC 0.890、F_final 0.054**(略差但不大)。**说明 critic 继承的贡献是「温和但真实」的,不是全部功劳所在。**
- **让 critic 也用旧任务样本 → NBT 0.037、AUC 0.888、F_final 0.067** —— **变差了**,直接支持「critic 只训当前任务」这一核心设计。

### 4. Replay 预算 N 的非单调性(Table 5,FORGE S1)

| $N$ | NBT ↓ | FWT ↑ | AUC ↑ | ACC_final ↑ | F_final ↓ |
|---|---|---|---|---|---|
| 10 | 0.107 | 0.853 | 0.854 | 0.847 | 0.192 |
| 20 | 0.093 | 0.844 | 0.859 | 0.869 | 0.167 |
| 50 | 0.060 | 0.838 | 0.871 | 0.900 | 0.104 |
| **100** | **0.040** | 0.854 | **0.896** | **0.925** | **0.062** |
| 200 | 0.043 | 0.842 | 0.879 | 0.903 | 0.083 |

**这是全文最有启发性的一张表,而且是一条反直觉结论:**

> 「保留**每任务 $N = 100$–200$ 条 episode(约占总 replay buffer 的 3%)** 提供了保持与学习的最优权衡。10–20 条的记忆不足以保持旧行为,而**把预算从 100 增加到 200 反而使性能下降**。这种非单调趋势表明,**有效的持续后训练并不直接来自『回放更多旧数据』。**」

**这条结论的产业含义比 ACCRUE 的主结果更重要:它是「更多数据 ≠ 更好」的一个干净反例,而且给出了明确的操作点(3% 的 replay)。**

### 5. 对基座遗忘的鲁棒性(Table 6,FORGE S1)

保持持续 RL 流程与 replay 预算不变,改变基座顺序微调时保留的旧任务演示比例:

| 演示保留 | $\pi_{base}$ 的 NBT ↓ | ACCRUE 的 NBT ↓ | ACCRUE FWT ↑ | ACCRUE AUC ↑ | ACCRUE ACC_final ↑ | ACCRUE F_final ↓ |
|---|---|---|---|---|---|---|
| **100%** | 0.013 | **0.028** | **0.854** | **0.906** | **0.961** | **0.037** |
| 50% | 0.035 | 0.056 | 0.817 | 0.860 | 0.908 | 0.092 |
| 10% | 0.090 | 0.078 | 0.811 | 0.844 | 0.875 | 0.133 |
| 5% | **0.163** | 0.071 | 0.836 | 0.859 | 0.894 | 0.113 |

**结论:即使基座本身在严重遗忘(演示只留 5%,基座 NBT 恶化到 0.163),ACCRUE 的 NBT 仍只有 0.071 —— 比 100% 演示保留时(0.028)差,但远好于基座自身的遗忘(0.163)。** 论文:「**ACCRUE 缓解了遗忘,并在基座本身遗忘时仍维持新任务的学习效率。**」

### 6. 基座无关性(Table 7,FORGE S1)

| 基座 | 方法 | Base SR | NBT ↓ | FWT ↑ | AUC ↑ | ACC_final ↑ | F_final ↓ |
|---|---|---|---|---|---|---|---|

## 局限性与未来展望

### 论文自述的局限(§6,作者明确写出)

1. **只在最长 5 阶段的接触装配序列上验证**,replay memory **每任务有界**。**「在固定总内存预算下把 ACCRUE 扩展到更长的任务序列」被明确列为 future work。**
2. **任务集窄**:「在更广泛的操作任务上评估 ACCRUE,**包括关联性更弱的任务**」是 future work。
3. **跨本体/跨动作空间迁移未做**:「学习共享动作表征、把 RL 后训练迁移到不同本体或动作空间」被列为自然的下一步。
4. **真机对照不完整**:论文明说「**我们只与同框架下的 single-task RL 对比,因为在这个规模上做完整的基线扫描不可行**」。

### 本报告阅读发现的问题

5. **真机的 31.0–68.5% 节省只对照了 weakest baseline。** 论文自己承认「完整基线扫描不可行」—— 这意味着**真机结果无法排除「任何 off-policy 初始化都能省这么多」的可能**。仿真侧有 6 个基线的完整对照(ER、EWC、RETAIN、Sequential),**真机侧一个都没有。** **这是全文最大的证据强度落差。**

6. **真机奖励由操作员标注,而旧任务保持也由人工评测 20 trials。** 论文未报告**标注一致性 / 操作员间一致性**。在 19/20 与 18/20 这种区分度上,**1 个 trial 的标注误差就是 5 个百分点。**

7. **$\beta$ 从 0.1 跳到 10.0,这个 100 倍差异没有解释也没有消融。** 论文只说「在硬件上把修正保持在 VLA 提议附近尤其重要,因为涉及物理接触」。**一个跨 100 倍的超参在真机上没做敏感性分析,是复现者最可能踩的坑。**

8. **Table 1/2 的 Isolated 行是「特权参考」而非可比基线 —— 但它其实赢了 ACCRUE。** FORGE 上 Isolated 的 AUC 0.868 / ACC_final 0.919 **略高于** ACCRUE 的 0.869(AUC 略高)/ 0.917(ACC 低)。AutoMate 上 Isolated AUC 0.879 / ACC 0.879 **高于** ACCRUE 的 0.858 / 0.863。**论文的表述是「在 AutoMate 上逼近了特权 Isolated 参考」—— 这个说法是准确的,但值得强调:「每任务存一个 learner」在 AUC 上仍然是更好的方案,ACCRUE 的价值在于存储成本,论文没有量化这个存储差异。**

9. **AUC 指标把「学习速度」与「保持」混在一个数里。** 见「核心公式提取」的提醒。**特别是 $c_{i,j} = c_{i,j,e^*_i}$ 取「最早达到最大值的 checkpoint」—— 这对旧任务有利(取峰值而非末期),会系统性抬高所有方法的旧任务分数。** 论文没有讨论这个选择的影响。

10. **与 [7] EXPO-FT / [36] RL Token 的关系是「叠加」而非「对比」。** ACCRUE 建立在这些轻量 off-policy 后训练方法之上,**但论文没有做「EXPO-FT + 承接 + 蒸馏」的完整消融**,因此**读者无法判断增益究竟来自「承接 critic」还是来自「actor 蒸馏」。** Table 4 的 `Reset Critic` 行(0.042 vs 0.028)只消融了 critic 继承,**没有消融 actor 蒸馏本身**(那需要去掉 Eq.4/5 的 $\lambda$ 项)。**这是消融表里最明显的缺口。**

11. **代码未释出。** 项目页明写 "Code (coming soon)",**无仓库**。对于一篇声称「简单但有效」的框架方法,缺代码会显著拖慢复现。

### 未来方向(论文提的 + 我们的推断)

**论文提的**:更长序列 / 固定总内存;更弱相关的任务;跨本体共享动作表征。

**我们的推断**:
- **「replay 非单调」这条发现应该被单独拿出去研究。** 为什么 100→200 会变差?论文只给了观察,**没给机制**。本报告的假设:$\mathcal{B}_{<k}$ 里旧任务样本越多,**1:1 采样比例下当前任务的梯度信号被稀释得越厉害** —— FWT 从 0.854(N=100)掉到 0.842(N=200)与此一致。**如果这个假设成立,那正确的解法不是限制 N,而是调整采样比例** —— 这是一个明确的、可立即验证的后续方向。
- **ACCRUE 与 HiFun 的方法论是同一个母题的两种答案。** HiFun 说「高层该有结构」,ACCRUE 说「高层该有承接」。两者都建立在同一个诊断上:**低层执行太难,不该让一个策略同时学。** 未来最可能的融合:**冻结的技能原语(HiFun)作为 ACCRUE 的动作空间**。
- **真机侧的对照缺失是可以由社区补上的。** 在 DROID 这种公开平台上,补做 ER / Sequential 的真机版只需要重新跑一遍 —— **这应当是社区的第一优先复现任务。**

## 应用与行业映射(本项目强制要求)

### 1. 应用方向

ACCRUE 的实验集高度聚焦于**接触丰富的精密装配**,以及它在论文中反复强调的**「任务到来」这一时间维度**。产业对应:

| 论文场景 | 产业对应 | 为什么重要 |
|---|---|---|
| **FORGE**:销插入、齿轮啮合、螺母攻丝 | **机械装配、精密插装、电子接插件、线束连接器** | 全部是**公差敏感 + 接触密集**的经典精密装配工序 |
| **AutoMate**(仿真) | **桌面级插座/插头装配、家电内部组装、连接器装配** | 5 个阶段、资产种类多 —— **这是「多 SKU 小批量」的典型形态** |
| **NIST Assembly Task Board**(真机) | **NIST 认证的工业装配基准** | 用标准板而不是自造工位,**说明作者在向可比较性靠拢** |
| **AutoMate**(真机,3D 打印件) | **仿真任务族直接迁到物理装置** | **验证「仿真学到的价值知识能不能迁到真机」** |
| **「新产品/新零件变体不断到来」** | **小批量多 SKU 产线、售后备件、现场部署的机器人** | **这才是本文真正的目标场景** —— 不是「学一个任务」,而是「**机器人要能持续吸收新任务**」 |

**受益最大的场景(本报告判断,排序):**

1. **多 SKU / 多变体的精密装配线**。今天的主流做法是「每个 SKU 一套离线数据 + 一个模型」,或者干脆退回人工。**ACCRUE 证明了一条新路:一个机器人 + 一个可承接的 learner,可以逐个吸收新装配任务。**
2. **产线换型 / 小批量的柔性制造**。**换型时间**是柔性产线的核心成本指标,而 ACCRUE 报告的正是「学新阶段所需机器人时间的减少」—— **这个数字直接对应换型停线时间。**
3. **现场部署的机器人(仓储、装配工位辅助)**。售后无法为每个客户现场重训;ACCRUE 的思路允许**任务在部署后逐步到来**。

### 3. 替代方案

**「让机器人持续吸收新任务」的四条路径:**

| 路径 | 代表 | 新任务所需交互 | 旧任务保持 | 存储成本 | 主要瓶颈 |
|---|---|---|---|---|---|
| **每任务一个模型** | **Isolated**(本文参考) | 完整 | **最好**(AUC 0.868/0.879) | **每任务一份 learner** | **存储与部署成本线性增长** |
| **每任务重启 RL** | **Single-task RL** | **完整**(真机对照基准) | 无冲突(不共享参数) | 单份 | **交互成本反复全额支付** |
| **On-policy 持续 RL** | **Simple Recipe** | 高(需当前策略新 rollout) | 好(NBT 0.038/0.016) | 单份 | **前向迁移弱**:FORGE 上 FWT 仅 0.586 |
| **持续学习正则化** | **EWC / RETAIN** | 中 | 差(AUC 0.582–0.704) | 单份 | **保持与学习互相牺牲**:EWC 把 FWT 压到 0.593 |
| **Experience Replay** | **ER** | 中 | **很差**(FORGE NBT 0.518、F_final 0.516) | 单份 | **旧数据喂 actor RL 会侵蚀旧行为(本文的诊断)** |
| **ACCRUE** | 本文 | **真机节省 31.0–68.5%** | **NBT 0.065/0.047** | **单份 + 每任务 3% replay** | **弱相关任务未测;真机对照只有 Single-task** |

| 项 | 数值 | 口径 |
|---|---|---|

> **本报告的成本判断**:**ACCRUE 的价值主张应被重新表述。** 它不是「让机器人学得更快」,而是 **「让机器人在固定内存下,逐个吸收新任务」**。**31–68.5% 的节省在实验室数字上不惊人,但它的产业意义在于:机器人从「一次性部署」变成「可生长部署」。** 这与 [[HiFun_2610.19518_研读报告|HiFun]] 那种「让单个工序更快」的改进,处在完全不同的价值层次上。

### 4. 量产壁垒

**按环节拆解(标注本文提供的证据强度):**

| 环节 | 壁垒 | 本文证据 |
|---|---|---|
| **① 算力 / GPU** | **不是瓶颈,但基座微调有门槛**。RL 本身轻量(FastSAC/FastTD3);**基座是 GR00T N1.7 全量微调(仿真)或 π0.5 LoRA(真机)** —— 真实门槛在「你得有一个能跑的基座」 | ✓ 强证据 |
| **② 基座模型依赖** | **中度门槛**。方法只通过 I/O 接口访问基座(论文明确「与 $\pi_{base}$ 内部架构无关」,Table 7 用 VLA 与 WAM 都验证),**但仍需基座先有一定成功率**(FORGE 用 10/20/50 条演示微调;真机用 5/10 条) | ✓ 强证据 |
| **③ 固定视觉编码器** | **轻度门槛,但有个隐藏耦合**:用 **DINOv3** 这类通用编码器 —— 意味着**放弃基座内部最强的视觉表征**。对「依赖细粒度视觉的任务」可能有代价,**论文未测** | ⚠️ 中等 |
| **④ 数据 / 演示** | **被大幅缓解**。每阶段仅需 **1–50 条**(仿真)/ **5–10 条**(真机)演示 —— **这是本文最具说服力的工程数字**。**但真机演示是 SpaceMouse 遥操作,仍需人工** | ✓ 强证据 |
| **⑤ 稀疏奖励的获取** | **真机的隐性大成本**。论文明确:**「奖励由操作员标注」**。每个 episode 都要人判断成败。**虽然比学习本身便宜,但这是一个持续的人力开销,论文未量化** | ⚠️ **中度 —— 论文未量化** |
| **⑥ 遗忘的绝对水平** | **不是瓶颈**。ACC_final **0.917 / 0.863**,相对未 RL 的基座提升 **23.0 / 10.6 个百分点**。**这说明「RL 后训练 + 承接」本身对精度有大幅增益,承接是在此之上的额外收益** | ✓ 强证据 |
| **⑦ 任务相关性** | **未测的边界**。论文自认需测「关联性更弱的任务」。⚠️ **当前证据只覆盖「高度相关的装配任务」。** 若新任务与旧任务不共享接触结构,**价值知识可能不可迁移,承接反而成为拖累** | ✗ **无证据 —— 最大的风险点** |
| **⑧ 真机对照完整性** | **弱**。只对照 Single-task,**ER / Sequential / EWC 的真机版一个都没有**。且论文承认「完整扫描不可行」 | ⚠️ 论文自述 |
| **⑨ 跨本体** | **完全未做**。论文列为 future work。**而「一台机器人多种本体」正是客户的现实诉求** | ✗ 无证据 |
| **⑩ 开源 / 复现** | **代码未释出** | ✓ 已核实(负面证据) |

**卡在哪一环?—— 本报告判断:卡在 ⑦ 和 ⑧。**

- **⑦(任务相关性未测)是**架构性**的**:ACCRUE 整个逻辑建立在一个隐含假设上 —— **「后续任务与已有任务足够相似,使得旧的价值估计仍然有用」**。证据:真机 AutoMate(任务高度相关)的节省是 **38.7–42.9%**,而 NIST(任务序列 3 阶段、差异更大)的节省是 **61.0–68.5%** —— **有意思的是关联性更弱的 NIST 节省反而更多,但两者的阶段数与任务设计都不同,不能直接推断。** 真正的答案是**未测**。**如果一个新 SKU 与旧 SKU 毫无接触结构相似性,承接来的 critic 就是一个有害的先验。**
- **⑧(真机对照缺失)是**证据性**的:31–68.5% 这组数字目前**只与「每任务从零开始」对比**。工业客户会问:**「如果我用 ER(经验回放)承接呢?」** —— **这个问题在真机上还没被回答。**

### 5. 时间窗估计

**1 年内(2026–2027)**

- **最可能落地**:**同产品族的换型**。比如同一款产品的不同零件变体、同一装配工序的不同来料公差。**这类场景任务高度相关,正是论文证据最强的区间。**
- **NVIDIA 会把 ACCRUE 收进 GR00T 生态的概率很高。** 理由:基座、仿真、算法、基准四件套都在 NVIDIA 手里。**若发生,它的可用性会远高于当前「无代码」的状态 —— 观察点是 GR00T 官方仓库的 release notes。**
- **代码释出是这一年的关键观察点。** 与 HiFun 同理:**「simple but effective」的框架类论文,没有代码的影响半径会大幅缩水。**
- **社区应补的第一件事**:在 DROID 上补做 ER / Sequential 的真机对照。**这是低成本、高价值的验证。**

**3 年内(2028–2029)**

- **「弱相关任务」是决定性未开区间。** 如果 ACCRUE 只能处理同族任务,**它的定位就是「产线换型加速器」**(仍然很有价值);如果能处理弱相关任务,**它就变成「机器人的终身学习框架」**(价值高一个量级)。**2029 年前这个问题的答案会决定它的估值。**
- **稀疏奖励的自动化是配套刚需。** 操作员逐 episode 标注不可扩展。**视觉/力觉的自动成功判别(参考 HiFun 的判别器路线)+ 少量人工校准,是必经之路。**
- **与 VLA 的关系**:ACCRUE 已经给出了最清晰的分工范式 —— **基座给提议,轻量 learner 给修正,承接保连续性。** 这个三层结构在 2029 年前应会成为 RFM 部署的标准形态。
- **跨本体**:论文列为 future work。**若某厂商能在 2029 年前证明「同一 learner 跨两种手/臂迁移」,这将是对「机器人操作系统」叙事的最强支持。**

**5 年内(2030)**

- **若持续学习成立,机器人软件的形态会改变**:今天机器人部署 = 一次性集成;**持续学习成立后的形态 = 部署一个会持续变强的 learner,任务按需到来。** 这会**大幅降低「为每个客户重新集成」的服务成本** —— 而这恰是当前机器人行业最大的成本项之一。
- **但风险同样明确**:安全认证。**一个会持续改变行为的机器人,在 ISO 10218 / ISO 13482 这类框架下如何认证?** 持续学习与「行为可验证」之间存在张力 —— **ACCRUE 的蒸馏机制(旧行为锚定到上一阶段 actor)意外地提供了一个可审计的抓手:旧行为的漂移被显式度量并惩罚。** 这可能是持续学习机器人能通过认证的关键机制,值得产业监管方关注。
- **颠覆性判断(本报告)**:**ACCRUE 本身不太可能成为独立产品** —— 它是 GR00T / π 系列之上的一个训练配方。**但「承接式后训练」很可能成为一个默认的机器人部署范式**,就像今天「预训练 + 微调」是默认一样。**真正的价值在于范式,而非某个框架。**

## 横向对比:机器人持续学习的三种做法

> 基于本文 Table 1–7 与 §5.1 基线定义的归纳。评分为本报告判断,非论文原文。

| 维度 | **Isolated**(每任务一份) | **参数正则化**<br>(EWC / RETAIN) | **经验回放**(ER) | **ACCRUE** |
|---|---|---|---|---|
| **共享参数** | 否(每任务独立) | 是 | 是 | **是(单一 actor–critic)** |
| **存储** | **每任务一份 learner** | 单份 | 单份 + 旧数据 | **单份 + 每任务 3% replay** |
| **FORGE AUC** | 0.868 | 0.582 / 0.682 | 0.697 | **0.869** |
| **FORGE NBT** | – | 0.217 / 0.514 | 0.518 | **0.065** |
| **FORGE FWT** | 0.816 | **0.593** / 0.802 | **0.833** | 0.823 |
| **AutoMate ACC_final** | **0.879** | 0.699 / 0.750 | 0.779 | 0.863 |
| **保持 vs 学习的权衡** | 保持最好,但学习也最好 —— **代价是存储线性增长** | **互相牺牲**(EWC 用 FWT 换 NBT) | **学得好、忘得也快** | **两者兼得,存储不变** |
| **真机验证** | ✗ | ✗ | ✗ | **✓(仅 vs Single-task)** |
| **跨基座** | — | — | — | **✓(VLA 与 WAM 均验证)** |
| **本质** | 回避问题 | 把保持写进损失 | 把旧数据当新数据 | **把保持写进「更新对象的范围」** |

**一句话总结**:
> **ACCRUE 的核心洞见是「不该让 critic 参与旧行为的维持」—— 遗忘不是记忆不够,而是错的损失项在错的样本上跑。把它拆成「critic 只学当前任务」+「actor 向旧 actor 蒸馏」,就把一个正则化问题变成了一个更新范围问题,因而可以做得更强也更干净。**
