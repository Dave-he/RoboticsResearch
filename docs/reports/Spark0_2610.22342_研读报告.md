## 核心问题

这篇论文提的**不是「加一个触觉传感器」,而是「触觉的监督信号身份」**。它把问题拆成三个缺口:

1. **数据缺口** —— 现有触觉数据集规模小、或缺同步的手部姿态与多视角视频。**机器人遥操作贵且接触类型窄**,所以必须转向人类演示采集。

2. **用法缺口(本文真正的靶心)** —— 触觉此前几乎只被当作**策略的输入**(condition / predict / feedback),**很少被当作「监督视觉表征」的训练信号**。这意味着:即使部署时手上没有触觉传感器,那份昂贵采集的触觉数据也**完全浪费**。

3. **评测缺口** —— 几乎没有基准能**在同本体上同时测「有触觉」和「无触觉」两种部署**,因此「触觉预训练到底带来了什么」根本无法被干净地回答。

论文由此提出的新视角是一句话:

> **触觉不仅是策略的输入,更是一种可规模化的「灵巧视动预训练监督」。**

Spark-0 的答案是一个**双角色设计**:触觉同时作为
- **仅训练期**的空间对齐监督信号(contact map + 3D 几何教师 → 监督视觉 token),推理时全部丢弃;
- **推理期**的接触动力学条件(触觉通路 → 只条件化 action expert)。

因此**一个 checkpoint 同时支持纯视觉部署和触觉条件化部署**。

## 方法论与核心思路

### 整体架构

```
                    ┌──────────────── 预训练期(触觉在此变成「监督」)────────────────┐
   人手套 → contact map ──渲染进头视角──► 与 DA3 几何教师一起 ──► 对齐 VLM 第 25 层 token
                                                        (Eq.3 几何 / Eq.4 接触,推理时全部移除)
   ┌────────────────────────────────────────────────────────────────────────┐
   │  Qwen3-VL-4B  ← ego RGB + 语言 + 离散化状态 + 64 个 action query      │
   └────────────────────────────────────────────────────────────────────────┘
                                    │ 逐层 hidden state {h_ℓ}
                                    ▼
   ┌──────────── Action Expert:36 层 DiT(偶数层 cross-attn 视觉 / 奇数层 self-attn)───────────┐
   │  关节序列:State ×3  +  Force ×12  +  3D ×12  +  Action ×50                                │
   │  触觉 token 只条件化 action expert,原始触觉**从不进入 VLM**                             │
   └────────────────────────────────────────────────────────────────────────────────────┘
                    │                                    │
        推理:纯视觉 → 触觉 token 换成学习到的占位符 e∅    推理:触觉条件 → 在线触觉信号
                    └──────────────► 同一套权重 ◄──────────────┘
```

### 关键设计 1:统一状态/动作空间(跨人类与机器人)

人类与机器人的手部形态、坐标系不同,所以所有来源**离线转换到目标本体的双手布局**。对侧 $k \in \{L, R\}$、时刻 $t$:

$$
s^k_t = \left( \rho\!\left(C_t^{-1} T^k_t\right),\, q^k_t \right), \qquad
a^k_{t+h} = \left( \rho\!\left((T^k_t)^{-1} T^k_{t+h}\right),\, q^k_{t+h} \right), \quad h = 0,\ldots,H-1
$$

**(Eq. 1)** —— 状态用头相机系下的绝对位姿,第 $h$ 个动作行用相对当前末端执行器的位姿 + 绝对关节目标;$\rho(T) = [p, r(R)] \in \mathbb{R}^9$ 用旋转矩阵前两行构成 6D 旋转表示,$\rho^{-1}$ 通过正交化恢复合法旋转。

两个刻意的设计:
- **相机帧作为共享的、以视觉为中心的参考系**,使人类视频和机器人数据在同一空间里对齐;
- **相对动作块在每个推理步重新锚定到最新观测位姿**,部署时由 $T^k_{t+h} = T^k_t \rho^{-1}(\hat a^k_{t+h})$ 恢复绝对目标。

拼接两侧得到 **$2 \times (9+20) = 58$ 维**(Eq. 1 后原文明确写出)。

> 📌 **值得注意的严谨处**:人类数据(HumanTouch 与 EgoDex)的腕部轨迹被配准到机器人系,手部关键点**通过逆运动学重定向到 WUJI Hand**。这意味着数据里隐含了一次**不可逆的信息损失**——人类手比 20 关节的 WUJI Hand 多自由度。重定向质量是全文未被消融的变量。

### 关键设计 2:Action Expert 与 flow matching 目标

Action Expert 用 $L = 36$ 个 DiT 块、宽度 1024。**偶数块 cross-attend 对应层的 VLM hidden state**(含 64 个 action query),**奇数块做 4.3 节的联合 self-attention**。给定归一化目标块 $a$、高斯噪声 $\epsilon$、flow 时间 $\tau \in [0,1]$:

$$
a_\tau = (1-\tau)\,\epsilon + \tau\, a, \qquad
\mathcal{L}_{\text{act}} = \mathbb{E}_{a,\tau,\epsilon} \left\| v_\theta(a_\tau, \tau, C) - (a - \epsilon) \right\|^2
$$

**(Eq. 2)** —— 其中 $C$ 表示连续状态、逐层 VLM 上下文、以及可选的触觉 token。损失对每样本 6 次噪声采样取平均,推理用 **4 步 Euler** 积分预测的速度。

**这个设计的巧妙之处**:因为 action expert 是**逐层**读 VLM 特征的,所以可以对**指定的那一层**施加监督 —— 这正是下一个设计的前提。

### 关键设计 3:仅训练期的空间对齐(角色一)

论文把监督加在 **VLM 第 $\ell^\star = 25$ 层** —— 原文措辞是「深但不是最后一层,会被 cross-attention 块读到」。两个头:

**(a) 几何对齐(Eq. 3)** —— 冻结的 **Depth-Anything-3(DA3)** 教师产生 patch 特征,重采样到合并后的视觉 token 网格:

$$
\mathcal{L}_{\text{geo}} = \mathbb{E}_{b,v,j} \left[ 1 - \cos \phi^{\text{geo}}\!\left( h^{(\ell^\star)}_{b,v,j},\, z^{\text{geo}}_{b,v,j} \right) \right]
$$

损失先在每个视角内平均、再跨视角平均,**以免 token 多的相机主导**。

**(b) 接触对齐(Eq. 4)** —— 对每只手,检测处于接触状态的 taxel,**锚定到由手套重建的 MANO mesh**,沿手表面扩散强度,渲染进头视角,**两只手按逐像素最大值合并**。该图池化到 token 网格成为软目标 $y_{b,j} \in [0,1]$,一个轻量 head 从头视角 token 预测接触 logits。因为接触区域稀疏,组合 focal 与 soft Dice:

$$
\mathcal{L}_{\text{con}} = 0.1\,\mathcal{L}_{\text{focal}} + 0.1\,\mathcal{L}_{\text{dice}}
$$

**关键声明:contact map 只是训练目标,绝不是策略输入。**

### 关键设计 4:触觉通路与「缺失触觉」处理(角色二)

空间对齐改善了「视觉能推断什么」,但**恢复不了被遮挡的压力变化**。所以另加一条触觉通路,**只喂给 action expert,原始触觉从不进 VLM**。

作者指出接触在**两个时间尺度**上演化:压力在毫秒级变化,而接触几何由单帧刻画。因此:

- **时序卷积**汇总每手 6 个区域各 **20 帧(≈333 ms)** 的力历史 → **12 个区域力 token**;
- **共享 point encoder** 嵌入当前每手 **320 个 taxel**(头相机系 xyz + 压力),在同一批区域内做注意力池化 → **12 个 3D token**。

**「缺失触觉」的处理是一个被低估的工程要点**:预训练数据只有一部分带触觉,而**传感器缺失 ≠ 零压力**。存在的流由独立的学习门缩放,缺失/无效的流使用**共享的学习占位符 $e_\varnothing$**。这个固定布局让纯视觉样本和触觉样本**可以混在同一个 batch**,而不会把「没感知到」误判为「没接触」。

**联合 action-tactile 流(Eq. 5)** —— 触觉 token 与 State、Action token 进入同一序列:

$$
Z_b = \left[ E_s(s_b) \;\Vert\; \tilde{e}^{\text{reg}}_b \;\Vert\; \tilde{e}^{3d}_b \;\Vert\; E_a(a_b) \right]
$$

共 3 个 State + 12 个区域力 + 12 个 3D + 50 个 Action = 77 个 token。三条防退化设计:

1. **非对称 attention bias** $b(g) = -6(1-\sigma(g))$:只限制**触觉 query 去看 State/Action key**;State/Action 看门控后的触觉 token **不加 bias**。目的是让触觉 token 保持「扎在感知上」。
2. **触觉旁路 dropout**:在带触觉的样本上,训练时**偶尔把 State 与 Action 行的 cross-attention 输出置零**,强迫上下文必须流经触觉行 —— 否则 action expert 可以完全绕开触觉通路。
3. **零初始化 AdaLN**:区域力窗口通过一条零初始化的 AdaLN 通路调制每个块。

### 关键设计 5:总目标与部署形态

$$
\mathcal{L} = \mathcal{L}_{\text{act}} + \lambda_{\text{geo}} \mathcal{L}_{\text{geo}} + \mathcal{L}_{\text{con}}, \qquad \lambda_{\text{geo}} = 0.2
$$

**(Eq. 6)** —— 几何对齐作用于所有可用视角,接触对齐作用于有效接触图,触觉编码器通过 $\mathcal{L}_{\text{act}}$ 在带触觉样本上学习。

**推理时**:DA3 教师与两个对齐头**被移除**,触觉旁路被禁用,**非对称 bias 与门控触觉通路保留**。同一套权重支持纯视觉部署(触觉位置填占位符)与触觉条件化部署(填在线信号),**不需要任何额外模块**。

## 关键成果与贡献

### SparkArena 基准(本文同时发布)

因为 Spark-0 用触觉有**两种方式**,评测也必须**分两条轨道**,且**固定同一灵巧本体**(Gen 1 Prototype,机器人形态与相机布局不变):

| 轨道 | 任务数 | 测什么 | 触觉 |
|---|---|---|---|
| **SparkArena-Sim** | **7** | 纯视觉灵巧控制(工具使用、精确驱动、双手抓取、约束取物、堆叠、物体收集、长程家务) | 部署时**无触觉** |
| **SparkArena-Real** | **5** | 视觉难以观测接触状态时的接触丰富控制(插装、柔性装配、精确定位、堆叠、物体重定向) | 部署时**用在线触觉** |

真实平台搭载 **Moxian 触觉手套**(与 HumanTouch 同 taxel 布局);仿真复现运动学与相机但无触觉。指标为**成功率(SR)与完成度分数(completion score)**:只有达成任务的**全部**目标才算成功,完成度分数按子目标给部分进度,**用来区分「接近成功」与「早期失败」**。真机因噪声大,**所有策略在配对初始条件下评测**。论文声明发布全部任务定义、资产、配对初始条件与评分协议。

**评测规模**:SparkArena-Real **每任务 10 trials**,SparkArena-Sim 50(Spark-0 的 SR 为 3 个随机种子的 mean ± standard error)。

| **Spark-0 (1000H)** | **36.86** | 无触觉部署 |

**批判性观察**:Spark-0 的逐任务最高分是 Click Mouse 42.00%,而**长程任务上多个基线为 0**。这意味着 Sim 轨道的**绝对水平仍然很低(36.86%)**,方法间的差距很大程度来自「基线在长程任务上彻底归零」,而非 Spark-0 本身接近可用。

### 结果 4:预训练与触觉规模消融(Table 4,本文最有价值的一张表)

| 变体 | SparkArena-Sim SR / Score | Ego Humanoid SR / Score | SparkArena-Real SR / Score |
|---|---|---|---|
| Spark-0 (Scratch) | 31.71 / 35.17 | 58.34 / 73.71 | 38.00 / 51.80 |
| Spark-0 (Visual PT) | 36.57 / 39.84 | 52.45 / 69.89 | 44.00 / 61.80 |
| Spark-0 (100H) | 35.14 / 38.01 | 59.42 / 76.72 | 40.00 / 52.00 |
| **Spark-0 (1000H)** | **36.86 / 39.74** | **71.72 / 83.37** | **52.00 / 62.80** |

定义:Scratch = 不预训练(从 Qwen3-VL 初始化);Visual PT = 用同一批 1000H 数据预训练但**丢弃触觉**;100H/1000H = 保留 100/1000 小时 HumanTouch 的触觉。

**四个必须仔细读的数字关系**:

1. **纯视觉预训练让跨本体迁移变差了**:Scratch → Visual PT,Ego Humanoid 从 **58.34% 降到 52.45%**(−5.89 点),虽然 Sim(+4.86)和 Real(+6.00)都在涨。**这是一个反直觉且重要的发现** —— 用大量 EgoDex 人类视频做视觉预训练,可能让模型过拟合到人类视角的视觉域,反而损害跨本体迁移。

2. **触觉是那 +19.27 分的来源**:Visual PT → 1000H 在**完全相同的 RGB 数据**上,Ego Humanoid 涨 **19.27 点**。因为 Ego Humanoid 测试时不用触觉,这个增益**只能来自触觉预训练**(通过 contact-map 监督视觉 token 与预训练好的触觉通路),而非在线触觉反馈。

3. **触觉规模是有门槛的**:Ego Humanoid 上 52.45%(0h)→ 59.42%(100h)→ 71.72%(1000h),**近似单调**;但 100H 在 Sim 和 Real 上**都没有超过 Visual PT**(35.14 < 36.57,40.00 < 44.00)。**只有 1000 小时这一档在三个基准上同时取得最好成功率。** 这对「要不要投人力采触觉数据」是一个明确的规模门槛信号。

4. **Sim 上触觉几乎无效**:Visual PT → 1000H 在 Sim 上只 +0.29。原文的解释是**接触监督主要改善的是对未见视觉域的迁移**,而 SparkArena-Sim 用的 Gen 1 Prototype 数据本来就在预训练里,所以边际收益小。**这个解释是自洽的,但也意味着 Sim 轨道对本文的核心贡献几乎没有鉴别力。**

### 预训练数据混合(Table 5,论文明确说明「曝光由采样权重决定,不由小时数决定」)

| 来源 | 小时 | 采样权重 | 视角 | 主要作用 |
|---|---|---|---|---|
| **HumanTouch** | **1,000** | **0.35** | 头 + 双腕 | **人类接触** |
| EgoDex | 662 | 0.39 | 头 | 场景与运动多样性 |
| 同款手套机器人 play | 20 | 0.09 | 机器人视角 | **本体与接触** |
| 机器人 play(触觉已移除) | 24 | 0.05 | 匹配视角 | 场景匹配的视觉控制 |
| 仿真 | 25 | 0.05 | 仿真 | 视觉域随机化 |
| Fourier ActionNet | 153 | 0.04 | 头 | 机器人任务多样性 |
| AgiBot World | 60 | 0.03 | 头 + 双腕 | 多视角机器人多样性 |

**触觉实际出现在 0.35 + 0.09 = 0.44 的采样概率上。**

> 📌 **一个未被论文讨论的成本结构**:HumanTouch 是 1,000 小时里**数据量第二小但采样权重最大(0.35)**的来源 —— 而 EgoDex 小时数最大(662)却只占 0.39 中的一部分。**换言之,预训练的有效样本分布被刻意向触觉倾斜,而这意味着一旦触觉数据不足,模型会反复看到同一批触觉样本。** 这与上面「100H 不够、1000H 才够」的门槛现象互为印证。

### 工程优化证据(Table III 式受控对比,本文内部的第三个受控实验)

在同一序列(NCD01)、**相同关键帧 / 初始化 / 采样 / 网络结构 / replay 数据 / 优化设置**下:

| 指标 | Tensor 实现 | 优化 C++/CUDA |
|---|---|---|
| Tracking (ms) | 79.674 / 167.922 (P95) | **35.076 / 58.016** |
| Mapping (ms) | 130.901 / 139.378 | **29.545 / 31.890** |
| Backend 合计 (ms) | 246.278 / 361.939 | **82.605 / 107.777** |
| 最终 ATE RMSE (m) | 0.2918 | 0.2835 |

平均后端延迟 246.278 → 82.605 ms(**−66.5%**),P95 361.939 → 107.777 ms(**−70.2%**),**而定位精度保持相当**。降幅最大的是 mapping(130.901 → 29.545 ms)。

**优化手段**:融合 CUDA 算子合并 query / 邻域聚合 / MLP 解码以减少中间张量、kernel launch 与显存带宽;tracking 不构建通用自动微分图而直接算梯度;冻结 MLP 解码器后用专用前向与输入梯度路径加速 mapping;预分配 workspace 减少重复分配。

## 局限性与未来展望

### 论文自述的局限

论文的 Conclusion 段**没有单列 Limitations 章节**,自我定位是「触觉预训练在完整 1000 小时规模下收益最大」。从实验设计可直接读出的边界:

1. **100 小时不够,1000 小时才够** —— 论文用 Table 4 的数字如实呈现了这一点,**但没有解释这个门槛的成因**(是数据多样性?触觉模式覆盖?还是单纯样本量?),也没有给出任何中间规模点(如 300h、500h)。**读者无法判断「要不要投 1000 小时」是全有全无还是渐进的。**

2. **Insert Test Tubes 无任何方法完全成功** —— 需要填满三个槽位的任务上,最好完成度只有 31.00。**在多插入类精密装配任务上,这套系统的绝对能力仍然很低。**

3. **未做重定向质量的消融** —— 人类手部关键点通过 IK 重定向到 20 关节的 WUJI Hand,这个不可逆映射的质量直接影响数据上限,但全文没有对应消融。

### 本报告阅读中发现的潜在问题

1. **460 vs 320 的 taxel 数字不一致(疑为表述差异,非错误)** —— §3.1 采集硬件写「每手 **460 个感知点**」,而 Figure 1 的图示与 §4.3 触觉编码器均写「每手 **320 个 taxel**」。合理解释是手套有 460 个物理感知点、其中 **320 个**被编码器使用,但**论文未明确说明筛选规则**。⚠️ 若要复现数据管线,这一点必须先确认。

2. **「Ego Humanoid 上 8 个指标全部第一」缺少逐项数字** —— 论文给出均值(71.72 / 83.37)与两个片段(28.79% 未见长程、通用 VLA 已见长程 <20%),但**没有列出 8 个聚合指标各自的数值与第二名**,外部无法独立核查「全部第一」的强度。⚠️ 这与本项目对「选择性披露」的既往观察一致。

3. **96 张 GPU 训练 400k 步,但未给 GPU 型号** —— Table 6 写「12 × 8 GPUs」,**未说明是 A100 / H100 / H800 还是其他**。这使得**复现成本无法估算**。按 Qwen3-VL-4B + 36 层 DiT + 576 全局 batch 的规模推断,96 卡训 400k 步的成本在**数十万美元量级** —— ⚠️ **此为本报告估算,非论文给出**。

4. **Sim 轨道对核心贡献缺乏鉴别力** —— 如前所述,SparkArena-Sim 上触觉只带来 +0.29 分,且多个基线(RDT-1B、EgoVLA)全任务为 0。**这条轨道目前更像是「基线过滤」而非「方法鉴别」。**

5. **仓库发布极晚** —— 仓库创建于 **2026-10-16 17:26 UTC**,论文标日期 2026-10-15,**仅 11 stars**。虽然内容是真实代码(`spark0/`、`configs/`、`third_party/`、`install.sh`、`pyproject.toml`),但**社区验证尚未开始**,上述任何复现结论都还没有第三方确认过。

### 未来方向(论文提的 + 本报告推断)

- **论文提的**:未展开;结论段聚焦于「触觉不只是策略输入,更是可规模化的监督」。
- **本报告推断**:
  - 触觉作为监督的思路**不依赖特定本体**(contact map 只需手部网格 + 接触点),因此**跨本体迁移可能进一步扩大** —— 目前只在 Ego Humanoid 上验证了一个本体。
  - 400 小时到 1000 小时之间的曲线形状,是判断「触觉数据工厂」ROI 的关键,**值得单独作为研究问题**。

## 应用与行业映射(本项目强制要求)

### 1. 应用方向

**核心受益场景:接触密集、视觉不可观测、且对精度有要求的灵巧操作。** 具体:

| 场景 | 为什么受益 | 受益程度 |
|---|---|---|
| **精密插装 / 装配**(电子、医疗器械、汽车零部件) | Insert Test Tubes 上「没有任何方法完全成功」→ 这正是最痛的地方;视觉看不出「插到一半卡住了」vs「没对准」 | ⭐⭐⭐⭐⭐ |
| **线缆 / 柔性物体操作** | 柔性物体形变无法从图像估计,但接触压力可以 | ⭐⭐⭐⭐⭐ |
| **易碎品抓取**(玻璃、陶瓷、生鲜) | 力历史(20 帧 ≈333 ms)直接对应「施力过大」与「初始滑动」 | ⭐⭐⭐⭐⭐ |
| **人形家务**(整理、收纳、装载洗碗机) | 本文 Ego Humanoid 场景;但长程任务绝对值仍低(28.79%) | ⭐⭐⭐ |
| **质量检测 / 装配验证** | 触觉作为「接触完成度」的客观信号 | ⭐⭐⭐⭐ |
| **仓储拣选** | 结构化环境,视觉相对充分,触觉边际收益较低 | ⭐⭐ |

**明确不适合**:纯自由飞行/导航(无接触)、大件搬运(触觉编码器为 20 关节灵巧手设计)。

### 3. 替代方案与成本量级

| 方案 | 机制 | 相对 Spark-0 的优劣 | 成本量级 |
|---|---|---|---|
| **纯视觉 VLA + 力矩传感器** | 用关节力矩代替表面触觉 | 无需额外传感器,但**测不到接触位置与分布**;NVIDIA GR00T-N1.7 在 SparkArena-Real 仅 16.00% SR 即为证据 | 力矩传感器通常已含在关节模组内,**边际成本≈0** |
| **视触觉专用策略**(如 FTP-1) | 触觉只作输入 | SparkArena-Real 36.00% vs 52.00%;**且 FTP-1 用了 200 h 机器人数据**,Spark-0 用 1000 h **人类**数据 | FTP-1:200 h 真机遥操作。**真机遥操作行业价约 $100–150/小时,200 h ≈ $20k–30k 人力** ⚠️ 价格为本报告估算 |
| **提高分辨率视觉**(如多相机 / 更高分辨率) | 用像素换精度 | 线性增加 LLM token 成本(见同日本日 [[FastVLA_2610.22146_研读报告\|FastVLA]]);且**物理上无法观测被手遮挡的接触** | 多相机方案边际硬件成本低,但**推理成本随视角数线性增长** |
| **力控 + 阻抗控制(经典方案)** | 纯控制论,不学习 | 在已建模的接触任务上仍强;但**无法覆盖长程、多阶段、非结构化接触** | 控制器方案无额外硬件成本,但**需要接触过程的人工建模** |
| **更大规模纯视觉预训练** | 加 EgoDex 小时数 | 本文数据直接显示:**更多人类视频让跨本体迁移变差**(58.34 → 52.45) | 数据成本 = 人类视频采集,通常比触觉数据便宜 ⚠️ 估价 |

**关键的成本判断**:本文证明了 **1,000 小时的人类触觉数据是有 ROI 的** —— 它把 Ego Humanoid 的跨本体成功率从 52.45% 推到 71.72%,且**这份数据可以在部署时完全不用触觉传感器**。换言之,**触觉数据的价值主要体现在预训练期,而不是部署期** —— 这大大降低了「每台机器人都要装触觉传感器」的硬件门槛。⚠️ **这个结论的成本含义是本报告的推断,论文未直接讨论。**

### 4. 量产壁垒(按环节拆解)

| 环节 | 壁垒内容 | 卡点评级 | 说明 |
|---|---|---|---|
| **① 触觉传感器硬件** | 全手覆盖的柔性压阻阵列,单手 460 感知点,需在 60 Hz 下与 6-DoF 腕追踪 + 多相机严格同步 | 🔴 **高** | 本文真机用 **Moxian 触觉手套**,即**可穿戴方案**。手套不是量产件,要从「手套」走到「装在机械手上」需要重新设计电极、耐久与标定 |
| **② 数据采集与人工** | **1,000 h × 32 名操作者**,且需同步手套 / 25 关节手部追踪 / 腕追踪 / 3 路相机 | 🔴 **高** | 论文明确指出 100 h 不够。**这是本文最硬的量化门槛**,也是「触觉数据工厂」的直接依据 |
| **③ 训练算力** | **96 张 GPU × 400k 步**(型号未给),微调另需 80k 步 | 🔴 **高** | ⚠️ 本报告估算为**数十万美元量级**。**这道门槛把绝大多数高校实验室与企业挡在外面**,只有大厂或国家实验室能承受 |
| **④ 本体重建(重定向)** | 人类手 → 20 关节 WUJI Hand 的 IK 重定向 | 🟡 **中** | 通用能力,但重定向质量直接影响数据上限,论文未开源规则 |
| **⑤ 本体一致性** | 触觉 taxel 布局必须与数据一致 | 🟡 **中** | 本文靠「同一手套既能戴在人手上、也能装在机器人手上」规避。**换本体就要重做布局映射** |
| **⑥ 基准与协议** | SparkArena 发布资产、配对初始条件、评分协议 | 🟢 **已缓解** | ✅ **这是本文对社区最实在的贡献**,把「有触觉基准几乎都在仿真」的问题部分解决 |
| **⑦ 绝对能力上限** | Insert Test Tubes 全员失败;长程任务 28.79% | 🔴 **高** | **对精密装配而言,当前 SOTA 仍不够用**。这是量产的现实卡点 |

**卡点指认:真正的量产卡点不在算法,在 ① 和 ②。**
算法侧(③④⑤)的门槛是「钱」,可以堆资源解决;但**触觉传感器的形态**(可穿戴手套 → 需装在机械手上)与**触觉数据的人力采集**(1000 h / 32 人)**是形态问题与人力问题,不是钱能直接解决的**。⚠️ 本报告判断。

### 5. 时间窗估计

**1 年内(2026–2027)**

- ✅ **可以落地**:把 Spark-0 的**预训练权重**作为起点,用于**已有触觉能力的手部平台**做下游适配。代码真开源,这是最现实的路径。
- ✅ **可以落地**:用「触觉作预训练监督、部署纯视觉」这条思路,给**没有触觉硬件的团队**提供一条提升灵巧操作的路(19.27 点跨本体增益是本文最硬的证据)。
- ❌ **不能落地**:把触觉手套直接改成机械手量产件。形态与耐久性问题至少需要一轮硬件迭代。
- ⚠️ **注意**:Spark-0 发布仅 1 天(仓库 2026-10-16 创建)。**任何「已落地」的判断在第三方复现出现前都应打折。**

**3 年内(2028)**

- 🔶 **规模化前提**:出现**手部集成式触觉传感器**(非手套形态)并把成本压到可接受量级。⚠️ **本报告不掌握触觉传感器的具体价格量级,故不给出价格预期** —— 给出数字会是编造。
- 🔶 触觉预训练从「论文方法」变成「预训练标配」,类比当前视觉预训练的地位。**主要驱动力会是跨本体迁移的 +19 点,而不是机器人本体的触觉覆盖率。**
- 🔶 出现第三方对照实验(如本文与 NVIDIA GR00T 的正面对比),使 Spark-0 的优势可被独立验证。

**5 年内(2030)**

- 🔵 **若成立**:触觉从「传感器品类」变成「数据品类」—— 就像今天的视觉,采集成本远高于存储/使用成本,价值在预训练期兑现。届时**没有触觉数据的团队会像今天没有图像数据的团队一样出局**。
- 🔵 **颠覆性潜力**:本文的「接触位置监督」本质上是**用触觉给视觉打补丁**。若这一范式成熟,视觉表征的质量上限会被重新定义 —— **触觉数据成为具身智能的「深度标签」**。
- 🔴 **反面情景**:若硬件形态(手套→手)迟迟不收敛,或 1000 小时数据的采集成本始终压不下来,触觉预训练会长期停留在**少数有资源的团队的专属优势**,而非行业基础设施。
